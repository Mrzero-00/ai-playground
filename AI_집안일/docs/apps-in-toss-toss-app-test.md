# 집토리 토스앱 최종 테스트 실행서

기준 문서: [미니앱 테스트하기](https://developers-apps-in-toss.toss.im/guide/operation/toss)

기준일: 2026-07-28

## 1. 코드에서 준비된 항목

- 앱인토스 Web Framework 2.10.6 사용
- 비게임(`partner`) WebView와 공식 내비게이션 바 명시
- 뒤로가기·홈·브랜드 제목 노출 설정
- 운영·비공개 테스트 Origin CORS 허용
- 앱인토스에서는 쿠키 대신 `getAnonymousKey` 기반 사용자 키 사용
- 운영 API는 HTTPS 주소만 사용하도록 환경변수 분리
- 화면 최상위 오류 상태와 다시 불러오기 제공
- 앱 내 기능 진입 경로 구현
- OG 전용 폰트를 서버 자산으로 분리해 미니앱 번들 용량 절감
- `.ait` 압축 해제 용량과 출시 설정 자동 검사

## 2. 출시 전 자동 점검

```bash
pnpm verify
pnpm ait:check
```

`pnpm verify`는 테스트, 타입 검사, 웹 빌드와 `.ait` 생성을 실행한다.

`pnpm ait:check`는 다음을 검사한다.

- `appName`, 브랜드 이름·색상·아이콘
- 운영·비공개 테스트 Origin
- 필수 운영 환경변수 항목
- SDK 1.4.0 이상 여부
- 600×600 PNG 로고
- `.ait` 압축 해제 용량 100MB 이하

출시 차단 항목이 있으면 `ait:check`는 실패 코드로 종료한다.

운영 Vercel을 배포한 뒤에는 다음 명령으로 DB·세션·초기 상태 API를 확인한다.

```bash
pnpm ops:check
```

## 3. 앱 내 기능 후보

콘솔의 앱 내 기능에는 사용자에게 의미가 명확한 이름과 아래 경로를 등록한다.

| 앱 내 기능 이름 | 경로 | 연결 화면 |
| --- | --- | --- |
| 오늘의 집안일 확인하기 | `/today` | 오늘 |
| 집안일 일정 확인하기 | `/schedule` | 일정 |
| 우리 집 집안일 관리하기 | `/chores` | 집안일 |
| 집안일 리포트 확인하기 | `/report` | 리포트·생활용품 |
| 내 살림 프로필 확인하기 | `/profile` | 내 정보 |

출시 전 테스트 스킴 예시:

```text
intoss-private://jiptori/chores?_deploymentId=<deploymentId>
```

정식 출시 후 스킴 예시:

```text
intoss://jiptori/chores
```

`intoss-private://` 스킴은 테스트에만 사용하고 사용자 공유 링크에는 사용하지 않는다.

## 4. 콘솔 업로드와 QR 테스트

1. 앱인토스 콘솔의 `appName`이 `jiptori`인지 확인한다.
2. 600×600 각진 정사각형 로고를 콘솔에 업로드한다.
3. 콘솔에 업로드한 로고의 HTTPS 링크를 `granite.config.ts`의 `brand.icon`에 입력한다.
4. `pnpm verify`와 `pnpm ait:check`를 다시 실행한다.
5. 생성된 `jiptori.ait` 파일을 앱 출시 메뉴에 업로드한다.
6. `테스트하기` 버튼으로 QR 코드를 연다.
7. 워크스페이스 멤버이면서 만 19세 이상이고 토스에 로그인된 기기로 QR을 스캔한다.
8. 최소 1회 이상 테스트를 완료한다.

테스트할 때마다 새 `deploymentId`가 발급되므로 이전 QR이나 테스트 스킴을 재사용하지 않는다.

## 5. iOS·Android 실기기 시나리오

- 첫 화면이 정상적으로 열리고 흰 화면이 보이지 않는다.
- 최초 화면에서 뒤로가기를 누르면 미니앱이 종료된다.
- 하위 앱 내 기능으로 진입한 뒤 뒤로가기와 홈 버튼이 정상 작동한다.
- 내비게이션에 집토리 로고와 이름이 표시된다.
- 집 생성 → 프로필 설정 → 추천 추가 → 완료 처리가 앱 안에서 끝난다.
- 다른 구성원이 초대 코드로 같은 집에 참여한다.
- 두 기기에서 같은 집을 수정했을 때 충돌 안내가 보인다.
- 앱을 닫고 다시 열어도 동일한 사용자의 데이터가 유지된다.
- 탈퇴 후 개인 데이터가 삭제되고 공유 집 데이터 보존 정책과 일치한다.
- 이용약관, 개인정보처리방침, 고객 문의 링크가 HTTPS로 열린다.
- 승인 전 토스쇼핑 제휴 링크가 노출되지 않는다.

## 6. 통신 점검

Vercel 운영 환경의 `ALLOWED_ORIGINS`에 아래 두 값을 정확히 등록한다.

```text
https://jiptori.apps.tossmini.com
https://jiptori.private-apps.tossmini.com
```

라이브 토스앱에서는 HTTP API가 차단되므로 `VITE_API_BASE_URL`은 HTTPS여야 한다.

iOS의 서드파티 쿠키 차단에 대비해 집토리는 앱인토스 환경에서 `getAnonymousKey`를 `X-Jiptori-User-Key` 헤더로 보내고, 일반 브라우저에서만 쿠키 폴백을 사용한다.

## 7. 장애 확인

화면 렌더링 오류가 발생하면 흰 화면 대신 다시 불러오기 화면을 제공한다. 출시 전에는 오류 모니터링 도구의 운영 계정·DSN·개인정보 마스킹 정책을 확정한다.

실기기에서 흰 화면이 발생하면 다음 순서로 확인한다.

1. 최신 토스앱인지 확인
2. `brand` 값에 빈 값이 없는지 확인
3. API가 HTTPS인지 확인
4. 운영·비공개 테스트 Origin이 CORS에 등록됐는지 확인
5. 이미지·폰트·초기 자바스크립트 용량 확인
6. 기기 로그와 오류 모니터링 기록 확인

## 8. CLI 업로드

콘솔에서 API 키를 발급한 뒤 다음 명령을 사용할 수 있다.

```bash
npx ait token add
pnpm ait:deploy -- -m "집토리 출시 후보"
```

API 키는 저장소, `.env.example`, 클라이언트 번들에 넣지 않는다.
