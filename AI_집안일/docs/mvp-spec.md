# 집토리 MVP 제품 요구사항

기준일: 2026-07-28

## 1. 제품 목표

집토리는 집의 거주 형태, 가구 구성, 아이 나이, 반려동물 종류와 마릿수를 바탕으로 필요한 집안일을 먼저 제안하고, 구성원이 같은 집의 할 일·수행 기록·생활용품 재고를 함께 관리하게 돕는다.

사용자가 처음부터 모든 정보를 입력하게 하지 않는다. 온보딩에서는 거주 형태, 가구 형태와 인원, 아이 나이, 주요 반려동물만 받고 방·욕실 수, 추가 동물과 세부 수량은 집 설정에서 보완한다.

## 2. 현재 범위

- 일반 브라우저 익명 쿠키와 앱인토스 `getAnonymousKey` 기반 사용자 식별
- 여러 집 생성과 초대 코드 참여
- 월세·전세·자가, 가구 형태, 아이 나이, 반려동물별 맞춤 추천
- 공통 핵심 집안일 자동 추가와 최대 6개의 우선 맞춤 추천
- 추천 추가·제외·30일 미루기와 선택 기억
- 커스텀 집안일의 이름, 분류, 아이콘, 일·주·월·년 반복, 개별 인앱 알림
- 집안일 활성화·비활성화, 완료와 당일 완료 취소
- 생활용품 소진일·안전재고 계산, 구매 업무 자동 생성, 구매 수량 기록·수정
- 추천되는 모든 집안일의 준비물·순서·주의사항 가이드
- 24문항 기획노동 진단, 공동·자동 업무 분배
- 월별 리포트, 구성원 수행 기록, 1년 범위 연속 달성
- 서비스 탈퇴와 개인 데이터 삭제

첫 출시에서 제외하는 항목:

- 토스 로그인
- 실제 푸시 발송
- 결제와 토스페이
- 생성형 AI 채팅 또는 동적 안내 생성
- 공개 순위와 소셜 공유

토스쇼핑 제휴 링크는 승인을 받고 환경변수를 설정한 출시에서만 노출한다.

## 3. 핵심 사용자 흐름

### 최초 시작

1. 집을 새로 만들거나 초대 코드로 참여한다.
2. 거주 형태와 가구 형태를 선택한다.
3. 가족 가구라면 필요한 경우 아이별 만 나이를 입력한다.
4. 강아지·고양이 여부를 선택한다.
5. 공통 핵심 집안일 8개가 기본 생성된다.
6. 아이·반려동물·거주 형태에 직접 관련된 추천을 먼저 확인한다.
7. 필요한 추천만 추가하고 필요 없는 추천은 제외하거나 미룬다.

### 오늘 할 일

1. 오늘 또는 이전부터 밀린 활성 업무를 반복 단위별로 본다.
2. 일반 업무는 완료 버튼으로 기록한다.
3. 생활용품 구매 업무는 `구매`를 눌러 실제 수량을 입력한 뒤 완료한다.
4. 오늘 완료한 일반 업무는 취소할 수 있다.
5. 완료한 구매 업무는 취소 대신 수량을 수정해 재고와 다음 구매일이 어긋나지 않게 한다.
6. 가이드가 있는 업무는 목록에서 즉시 준비물·순서·주의사항을 확인한다.

### 공동 집

1. 집 소유자가 6자리 초대 코드를 공유한다.
2. 다른 구성원이 코드로 참여한다.
3. 변경 내용은 현재 선택한 집 한 곳만 서버에 저장한다.
4. 서버 집 버전이 달라졌다면 오래된 화면의 저장을 거부하고 최신 내용 다시 불러오기를 안내한다.
5. 동기화된 화면은 30초 간격과 창 재진입 시 다른 구성원의 변경을 확인한다.

## 4. 추천 원칙

- 기본값은 설거지, 환기, 분리수거, 화장실, 바닥, 수건, 침구, 냉장고 유통기한의 8개 핵심 업무다.
- 나머지 업무를 처음부터 모두 추가하지 않는다.
- 아이 나이, 반려동물, 월세·전세·자가, 가구 형태에 직접 관련된 업무를 일반 청소보다 먼저 추천한다.
- 한 번 제외한 추천은 서버와 로컬에 저장해 재접속 후 다시 자동 추가하지 않는다.
- 추천 주기는 사용자가 변경할 수 있고, 추천 업무도 사용하지 않거나 삭제할 수 있다.
- 테스트용 전체 가이드와 휴지 데이터는 `VITE_ENABLE_DEMO_DATA=true`일 때만 생성한다.

## 5. 데이터와 동기화

- Supabase가 공동 데이터의 원본이며 로컬 저장소는 빠른 표시와 장애 시 캐시다.
- API는 사용자가 해당 집 구성원인지 확인한다.
- 클라이언트가 전달한 다른 사용자의 수행자로 새 기록을 만들 수 없다.
- 집 저장은 PostgreSQL 함수 안에서 원자적으로 처리한다.
- 추천 선택, 집안일, 수행 기록, 노동 진단, 생활용품을 같은 집 버전으로 저장한다.
- 사용자 입력은 API에서 길이, 수량, 열거형, 날짜 형식을 검증한다.
- 내부 서버 오류와 비밀 정보를 클라이언트 응답에 포함하지 않는다.

## 6. 생활용품 계산

- 구매 수량과 주간 사용량은 1 이상의 정수 입력을 기본으로 한다.
- 안전재고와 미리 확인할 날짜는 0을 허용한다.
- 예상 안전재고 도달일은 `(구매 수량 - 안전재고) / 주간 사용량 × 7일`을 반올림해 계산한다.
- 확인일은 예상 도달일에서 `며칠 전 확인`을 뺀 날짜다.
- 확인일부터 활성 구매 업무가 오늘 목록에 표시된다.
- 실제 사용 이력이 없는 상태에서는 가상의 주간 추세 그래프를 만들지 않는다.

## 7. 가이드 품질

- 모든 추천 템플릿에는 준비물 2개 이상, 순서 4단계 이상, 주의사항 2개 이상을 제공한다.
- 세탁기·건조기·전자레인지 등 제품 차이가 큰 업무는 사용설명서를 우선하도록 표시한다.
- 표백제와 다른 세정제 혼합, 전기·가스 임의 수리, 아이 삼킴, 반려동물 독성처럼 위험도가 높은 내용을 명시한다.
- 계약·보증 가이드는 일정과 서류 관리 범위로 제한하고 법률 판단을 대신하지 않는다.
- 고양이 화장실은 모래 보충·전체 교체·임신 또는 면역저하자의 주의를 구분한다.

## 8. 완료 기준

변경사항은 다음을 모두 통과해야 완료다.

1. `pnpm test`
2. `pnpm typecheck`
3. `pnpm build`
4. `pnpm ait:build`
5. 모바일 390px과 태블릿 768px에서 가로 스크롤이 없음
6. 온보딩, 추천, 오늘 할 일, 가이드, 생활용품 숫자 입력을 실제 브라우저에서 확인
7. Supabase 마이그레이션 적용 후 두 사용자의 초대·동시 저장·탈퇴 시나리오 확인

## 9. 출시 전 남은 외부 입력

- 앱인토스 콘솔에서 확정한 `appName`과 아이콘 URL
- 운영 문의 이메일
- 이용약관·개인정보처리방침·고객 문의 HTTPS URL
- 복구된 운영 Supabase 프로젝트와 네 개 마이그레이션 적용
- Vercel 운영 환경변수와 Toss Origin
- 토스쇼핑 제휴 및 외부 이동 승인 여부
- iOS·Android 토스 샌드박스 실기기 결과
