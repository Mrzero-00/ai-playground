# 냥BTI 질문·스코어링 데이터셋 v0.1

> **문서 상태: 재구성된 v0.1 작업본 (reconstructed working edition)**
> 최초 대화에서 생성된 canonical Markdown 첨부파일을 현재 작업 환경에서 찾을 수 없어, 이 문서는 현재 실행 코드인 `data/questions.ts`, `lib/scoring.ts`, `types/nyangbti.ts`를 기준으로 역문서화했다. 원본 첨부가 복구되기 전까지 코드와 QA의 기준으로 사용할 수 있지만, 최초 기획 문서와 동일하다고 간주하면 안 된다.

## 1. 적용 범위와 버전

- 문항 수: 30개
- 내부 연속 Trait: `sociability`, `boldness`, `activity`, `playfulness`, `adaptability`, `sensitivity`
- 각 주 Trait별 문항: 5개
- 응답 방식: 0~4의 5점 척도
- 결과: 6개 Trait 점수(0~100) → 4개 냥BTI 축 → 16개 코드
- 현재 코드에는 별도의 `questionSetVersion` 또는 `scoringVersion` 필드가 없다.
- Zustand 저장 키는 `nyangbti-survey-v1`, 저장소 버전은 `1`이다.

생년월일, 품종, 성별, 중성화 여부와 집사 MBTI는 현재 Trait 스코어링에 관여하지 않는다. 특히 품종·성별에 따른 고정 성향 보정은 사용하지 않는다.

## 2. 공통 응답 척도

| 값 | 화면 문구 | 짧은 문구 | 중심화 값 `value - 2` |
|---:|---|---|---:|
| 0 | 거의 그렇지 않아요 | 거의 안 그래요 | -2 |
| 1 | 드물게 그래요 | 드물게 | -1 |
| 2 | 가끔 그래요 | 가끔 | 0 |
| 3 | 자주 그래요 | 자주 | +1 |
| 4 | 거의 항상 그래요 | 거의 항상 | +2 |

현재 UI에는 `건너뛰기`가 없으며, 각 문항에 답해야 다음 문항으로 이동할 수 있다. 결과 페이지도 30개 문항이 모두 저장되어야 진입할 수 있다. 다만 스코어러를 직접 호출할 경우 누락된 답은 `2`, 즉 중립 응답으로 처리한다.

## 3. 가중치 표기

아래 표에서 축약어는 다음을 뜻한다.

| 축약 | Trait |
|---|---|
| `SOC` | sociability |
| `BOL` | boldness |
| `ACT` | activity |
| `PLY` | playfulness |
| `ADP` | adaptability |
| `SEN` | sensitivity |

한 문항의 실제 기여도는 `중심화 응답 × 가중치`다. 예를 들어 응답 `4`, 가중치 `-1`인 역문항은 해당 Trait에 `-2`를 더한다.

## 5. Trait 계산과 0~100 정규화

각 질문 `q`, Trait `t`에 대해 다음 값을 누적한다.

```text
answer(q)   = clamp(저장된 값 또는 2, 0, 4)
centered(q) = answer(q) - 2

raw[t] += centered(q) × weight(q, t)
min[t] -= 2 × abs(weight(q, t))
max[t] += 2 × abs(weight(q, t))
```

정규화 공식은 다음과 같다.

```text
range[t] = max[t] - min[t]

normalized[t] =
  range[t] == 0
    ? 50
    : (raw[t] - min[t]) / range[t] × 100

result[t] = roundToOneDecimal(clamp(normalized[t], 0, 100))
```

현재 데이터셋의 절대 가중치 합과 이론적 범위는 다음과 같다.

| Trait | `Σ abs(weight)` | 이론적 최소 | 이론적 최대 | 범위 |
|---|---:|---:|---:|---:|
| sociability | 5.10 | -10.20 | 10.20 | 20.40 |
| boldness | 5.75 | -11.50 | 11.50 | 23.00 |
| activity | 5.35 | -10.70 | 10.70 | 21.40 |
| playfulness | 5.40 | -10.80 | 10.80 | 21.60 |
| adaptability | 5.65 | -11.30 | 11.30 | 22.60 |
| sensitivity | 6.15 | -12.30 | 12.30 | 24.60 |

이론적 최댓값은 해당 Trait의 양수 가중치 문항에는 `4`, 음수 가중치 문항에는 `0`을 선택했을 때 달성된다. 따라서 모든 문항에 일괄적으로 `4`를 답한다고 모든 Trait이 100이 되는 구조는 아니다.

## 6. 6개 Trait → 4개 냥BTI 축

### 6.1 첫 글자 점수

```text
E score = sociability

N score =
  boldness × 0.45
  + adaptability × 0.35
  + (100 - sensitivity) × 0.20

F score =
  sociability × 0.50
  + sensitivity × 0.30
  + (100 - boldness) × 0.20

P score =
  playfulness × 0.55
  + activity × 0.30
  + adaptability × 0.15
```

코드 내부 축 키와 사용자 의미는 다음과 같다.

| 코드 키 | 첫 글자 / 둘째 글자 | 화면 라벨 |
|---|---|---|
| `EI` | E / I | 교류 에너지 |
| `NS` | N / S | 탐색 방식 |
| `TF` | F / T | 반응 방식 |
| `JP` | P / J | 생활 리듬 |

첫 글자 점수가 `50 이상`이면 첫 글자, `50 미만`이면 둘째 글자를 선택한다. 정확히 50인 경우 각각 E, N, F, P 쪽으로 결정된다.

```text
selectedStrength = 50 + abs(firstScore - 50)
                 = max(firstScore, 100 - firstScore)
```

축 경향 수준:

- `75 이상`: 높음
- `61 이상 75 미만`: 중간
- `61 미만`: 낮음

최종 코드는 `EI.selected + NS.selected + TF.selected + JP.selected` 순서로 만든다.

### 6.2 Trait 자체 수준

결과 페이지의 6개 Trait 라벨은 별도 기준을 사용한다.

- `40 미만`: 낮음
- `40 이상 65 미만`: 중간
- `65 이상`: 높음

## 7. 현재 구현 불변조건과 엣지 케이스

- 문항 ID는 답변 저장 키이므로 배포 후 의미를 바꾸거나 재사용하면 안 된다.
- 각 문항은 0~4 정수 응답을 전제로 한다. 스코어러는 범위를 clamp하지만 소수·`NaN`을 명시적으로 거부하지 않으므로 UI와 저장소에서 유한 정수만 넣어야 한다.
- 알 수 없는 답변 ID는 계산에서 무시된다.
- 누락된 정식 문항 답변은 스코어러에서 2로 처리된다. 현재 UI는 30문항 완료를 강제하므로 정상 경로에서는 발생하지 않는다.
- 응답 `2`는 모든 가중치에 대해 기여도가 0이므로 전체 중립 응답은 6개 Trait 모두 정확히 50이다.
- 답변을 `value → 4 - value`로 모두 뒤집으면 raw 점수가 부호 반전되므로 각 Trait은 이론상 `100 - 기존 점수`가 된다. 소수 첫째 자리 반올림을 고려한다.
- 결과 유형은 엔터테인먼트성 행동 분류이며, 사람의 MBTI 검사나 수의학적 진단이 아니다.
- 최근의 갑작스러운 놀이·활동 감소 등은 성향 점수와 분리해 Behavior Check와 수의 상담 안내로 다뤄야 한다.

## 8. 현재 자동 테스트

`lib/scoring.test.ts`는 현재 다음을 검증한다.

1. 30문항에 모두 `2`를 답하면 6개 Trait이 모두 50이다.
2. 모든 문항에 `0` 또는 `4`를 답한 경우 모든 Trait이 0~100 범위에 있다.
3. 최종 4글자 코드가 네 축의 `selected` 값을 순서대로 결합한 값과 같다.

추가 권장 테스트:

- 문항 30개, ID 중복 없음, 각 주 Trait별 정확히 5개인지 검증.
- 모든 가중치가 유한 숫자인지 검증.
- 역문항을 포함한 Trait별 이론적 최소·최대 답변에서 각각 0과 100인지 검증.
- 모든 답변 반전 시 보완 점수가 되는지 검증.
- 축 공식과 정확히 50인 경계의 글자 선택을 고정 fixture로 검증.
- `TYPE_CONTENT`가 가능한 16개 코드 모두를 포함하는지 검증.
- 잘못된 `NaN`, 소수, 범위 밖 응답에 대한 정책을 정하고 검증.
