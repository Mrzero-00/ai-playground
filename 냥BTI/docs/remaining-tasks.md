# 냥BTI 잔여 작업

최종 정리일: **2026-08-25 (Asia/Seoul)**

현재 로컬 웹 MVP에서 바로 해결 가능한 개발·테스트 작업은 완료했다. 아래는 사용자 계정, 외부 승인, 실제 기기 또는 전문 검토가 있어야 진행할 수 있는 작업이다.

## 1. 사용자 계정·승인이 필요한 필수 작업

- [ ] App in Toss 콘솔에서 미니앱을 **비게임(partner)** 으로 등록하고 실제 `appName`, 워크스페이스, 국문 표시명, 브랜드 색을 확정한다. `appName`은 등록 후 변경할 수 없으므로 제출 전에 철자를 확정한다.
- [ ] 600×600 불투명 PNG 로고, 1932×828 PNG 썸네일, 고객센터 연락처를 준비한다. 홈 노출을 원하면 세로 636×1048 PNG 스크린샷을 최소 3장 준비한다.
- [ ] `.env.example`을 `.env.ait`로 복사하고 콘솔의 `appName`, 표시명, 로고 URL을 입력한 뒤 `pnpm build:ait`로 `.ait` 번들을 만든다. SDK 2.10.8과 Granite 설정은 적용됨.
- [ ] 실제 콘솔이 SDK 3.x를 권장 또는 요구하는지 확인한다. 현재 2.10.8은 공식 최소 2.x 요건을 충족하며, npm 최신 3.1.1 업그레이드는 별도 마이그레이션 QA가 필요하다.
- [ ] 사업자·정산 정보를 등록하고 검토를 받은 뒤 광고 그룹을 생성해 테스트/운영 광고 ID를 발급받는다.
- [ ] 토스 워크스페이스 멤버 계정과 실제 iOS·Android 기기로 QR 테스트를 1회 이상 완료한다.
- [ ] 콘솔에서 비게임 미니앱 검토를 요청하고, 승인 후 사용자가 직접 `출시하기`를 실행한다.
- [ ] 현재 작업물을 검토한 뒤 배포 기준 커밋/태그를 만들고, 승인된 `.ait`와 이전 안정 번들을 함께 보관한다.

## 2. App in Toss 실환경에서 마무리할 개발·QA

- [ ] 구현된 `graniteEvent`, `closeView` fallback, `SafeAreaInsets`, Toss share 경계를 iOS/Android QR 실기기에서 확인한다.
- [ ] 발급받은 운영 광고 ID를 `.env.ait`에 설정하고 `onNoFill`·클릭 후 복귀·빈 영역 제거를 실기기에서 확인한다.
- [ ] `.ait` 압축 해제 용량이 100MB 이하인지 측정하고 QR·라이브 Origin에서 CORS와 공유 동작을 재검증한다.

자세한 실행 체크리스트는 [`app-in-toss-checklist.md`](app-in-toss-checklist.md)에 있다. SDK 버전과 정책은 연동 직전 다시 확인한다.

## 3. 외부 전문 검토·운영 준비

- [ ] 수의행동 전문가가 30문항, 가중치, 결과 문구와 생활 관리 팁을 검토한다.
- [ ] 충분한 실제 응답 데이터를 모아 Trait 분포, 4축 경계, 궁합 점수 분포를 보정한다.
- [ ] 고객 문의 채널과 운영 책임자를 확정한다. 현재 앱은 토스 로그인·서버 전송 없이 기기 `localStorage`만 사용하지만, 실제 콘솔이 요구하거나 로그인/사용자정보 기능을 추가하면 공개 개인정보 처리방침·이용약관 URL과 데이터 파기 절차를 준비한다.
- [ ] 출시 후 오류·성능·사용자 이탈을 확인할 모니터링과 장애 대응 절차를 준비한다.

## 4. 구현 완료된 후속 기능

- [x] 여러 고양이 프로필과 결과 이력 관리
- [x] 고양이 간 생활 조화와 고양이별·공통 관리 팁
- [x] 앱인토스 네이티브 공유와 링크 수신자용 결과 화면

## 5. 선택형 운영 개선

- [ ] 익명 분석 이벤트와 설문 이탈 지점 측정
- [ ] 계정·서버 동기화 또는 기기 변경 복구
- [ ] 실제 사용자 대상 접근성·가독성·문항 이해도 테스트

이 항목들은 현재 MVP 실행과 결과 계산에 필수는 아니다.
