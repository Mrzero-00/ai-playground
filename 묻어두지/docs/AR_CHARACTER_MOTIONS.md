# 두지 3D 캐릭터 · AR 모션 제작안

작성일: 2026-09-17

상태: 연출·제작 설계 및 생성 설정 준비. 실제 캐릭터 3D 파일과 아래 모션은 아직 제작되지 않았고 앱 코드에도 추가하지 않았다. 이미지 원화 시안과 AR 캡슐 도형은 존재한다. fal 연결·모델 입력 형식·공개 요금은 확인했으나, B 원화의 외부 업로드가 자동 안전 검토에서 차단되어 사용자 승인 대기 중이다. 업로드 성공 URL이나 생성 작업 ID는 없으며 유료 생성은 실행하지 않았다.

## 방향

삽을 든 B 시안을 기준 후보로 삼는다. 최종 캐릭터 선택으로 확정한 것은 아니다. 재료감은 부드러운 갈색 털과 하늘색 스카프, 성격은 능청스럽지만 사용자의 약속은 지키는 작은 일꾼이다.

원화의 정교한 털을 모바일 AR에서 그대로 재현하는 것은 별도 문제다. 우선 둥근 실루엣과 얼굴 인상을 보존하고 털 느낌은 재질로 표현한다. 실제 기기에서 성능을 확인한 뒤 디테일을 늘린다.

## 세 가지 대표 모션

아래 시간은 제작 목표이며 실제 애니메이션 클립을 보고 조정한다.

| 모션 | 목표 길이 | 연출 | 끝 문구 |
| --- | --- | --- | --- |
| 묻기 | 약 5~6초 | 자리 확인 → 두 번 삽질 → 캡슐을 조심스럽게 넣기 → 흙 덮고 삽으로 톡톡 → 뿌듯하게 끄덕 | 잘 묻었어. 나도 안 볼게. |
| 꺼내기 | 약 5~6초 | 귀를 땅에 대기 → 신나게 삽질 → 캡슐을 들고 올라오기 → 흙을 털고 사용자 쪽으로 내밀기 | 이거 기다렸지? |
| 잠금·실망 | 약 3초 | 삽을 내리려는 순간 땅에 자물쇠 문양 → 삽 끝이 통 하고 튕김 → 고개 갸웃 → 어깨와 삽을 축 늘어뜨림 | 땅도 약속은 지키네… |

잠금 동작은 벌이나 경고가 아니라 가벼운 코미디다. 충돌 이펙트·효과음은 짧고 작게, 음소거와 동작 줄이기를 지원하는 방향으로 설계한다. 실망한 뒤 기본 대기로 돌아가며 무한 재생하지 않는다.

## 땅 연출

실제 카메라에 보이는 바닥을 뚫거나 변형하는 기능이 아니다. 인식한 평면 위에 작은 가상 흙판과 구멍의 테두리·안쪽을 놓아 파는 것처럼 보이게 한다. 두지와 캡슐이 구멍 아래로 사라지는 구간은 흙판의 가림과 연출로 처리한다. 깊이 가림의 품질과 밑에서 보는 각도는 실기기 확인이 필요하다.

기존과 같이 방문 시 새로 인식한 바닥에 배치한다. 과거에 묻은 정확한 AR 지점을 복원하는 기능으로 표현하지 않는다.

## 제작 경로와 필요한 자산

1. 기준 캐릭터를 정하고 정면·측면·후면, 팔다리가 몸과 겹치지 않는 기본 포즈를 준비한다. 삽·캡슐은 캐릭터 몸에서 분리한다.
2. 이미지 기반 AI로 3D 몸체 초안을 만든다. 얼굴, 손발, 뒷면, 스카프와 피부의 분리 여부를 검사한다.
3. 관절과 피부 변형을 설정한다. 짧은 팔다리를 가진 두지는 자동 사람형 리깅 실패나 손발 변형 가능성이 있어 검수가 필요하다.
4. Blender에서 삽 잡기, 캡슐 잡기·놓기, 고개·어깨 연기, 흙판 변화를 맞춘다. 일반 걷기/뛰기 프리셋을 적용한 결과를 요청한 세 모션으로 간주하지 않는다.
5. 모바일용 모델과 이름이 붙은 애니메이션을 내보내고 앱에서 재생·중단·복귀를 확인한다.

제작할 자산: 두지 몸체와 재질, 관절, 삽, 캡슐, 흙판·구멍, 잠금 문양, 흙 파편 효과. 단독 검수가 가능하도록 원본 Blender 파일도 유지한다.

권장 납품 형식은 GLB이며 실제 내보내기와 iOS/Android 호환성을 검증한다. 모델만 있는 GLB와 애니메이션까지 들어 있는 GLB를 구분한다. 애니메이션 클립명은 제작 후 런타임에서 존재 여부를 확인하고 확정한다.

| 클립 후보 | 역할 |
| --- | --- |
| Idle | 기본 대기, 반복 |
| DigLoop | 흙 파기, 필요 시 짧게 반복 |
| BuryFinish | 캡슐 넣기·흙 덮기·마무리 |
| RetrieveFinish | 캡슐 꺼내기·사용자에게 내밀기 |
| LockedDisappointed | 잠금 충돌·실망·대기 복귀 |

성능 초안 목표는 캐릭터와 주요 소품 합계 약 2~3만 삼각형, 텍스처 1K부터 시작, 실제 기기 30fps 이상이다. 이는 앱의 보장 수치나 도구의 제한이 아니라 검증을 시작하기 위한 예산이다.

## 앱과 연결할 때 지킬 규칙

- 봉인 요청 중에는 짧은 대기/삽질만 가능하다. 서버가 생성 성공을 반환한 다음에만 BuryFinish와 완료 문구를 보여준다. 응답 유실 시 기존 Idempotency-Key 복구를 유지하고 성공 모션을 앞질러 재생하지 않는다.
- 개봉 조건 확인은 사전 안내일 뿐이다. 실제 내용 요청 시 서버가 시간·소유권·신선한 GPS·거리·정확도를 다시 검사한다. 성공 응답 후 RetrieveFinish를 재생하고 내용 화면으로 이동한다.
- 잠금·실망은 서버의 시간 미도달 결과에만 사용한다. 현장 연출을 할 때는 장소와 GPS 조건도 확인한다. 너무 멀거나 GPS가 부정확하면 해당 원인을 안내한다.
- 통신 실패·권한 거부·AR 추적 실패를 자물쇠나 실망 모션으로 감추지 않는다. 무엇을 다시 시도해야 하는지 표시한다.
- 잠금 모션에는 실제 편지·사진·영상·음성이나 그 미리보기를 넣지 않는다.
- 앱이 백그라운드로 가거나 AR을 닫으면 모션·효과음·재생용 본문을 정리한다. 뒤늦은 응답은 이전 화면을 되살리지 않는다.
- 모션 건너뛰기는 표현만 생략한다. 서버의 저장·개봉 조건을 건너뛰는 기능이 아니다.
- 모션 로드나 재생이 실패하더라도 이미 성공한 서버 작업을 취소된 것으로 표시하지 않는다. 실제 결과에 맞는 정적 화면으로 전환한다.

현재 코드에서는 성공 응답 직후 AR을 닫으므로, 자산이 준비되면 서버 작업 완료와 화면 전환 사이에 모션 단계를 넣어야 한다. 또한 현재는 개봉 가능할 때만 AR을 여므로, 시간 잠금 연출은 본문 없는 별도 AR 표현 상태가 필요하다.

## 확인한 제작 도구와 제약

- 현재 앱의 ViroReact 2.57.3에는 GLB 모델·모프 타깃 API가 있고, 공식 문서는 모델 안의 이름 붙은 애니메이션 재생을 안내한다. 실제 모델과 기기로 검증하기 전에는 동작 완료로 간주하지 않는다. [Viro 문서](https://viro-community.readme.io/docs/animated-glb-models)
- fal에는 Meshy 이미지→3D, GLB 출력, 사람형 자동 관절 설정과 기본 애니메이션 경로가 있다. 팔다리가 분명한 사람형 모델을 권장하므로 이 캐릭터의 자동 리깅 성공은 보장하지 않는다. [Meshy on fal](https://fal.ai/models/meshy/v7/image-to-3d/api)
- fal 연동이 연결되어 모델 추천·입력 형식·공개 요금을 조회했다. `fal-ai/nano-banana-pro/edit`로 동일 캐릭터의 삽을 제거한 기본 자세를 만들고, `meshy/v7/image-to-3d`로 몸체·관절을 생성할 계획이다. Meshy의 A-pose, 자동 사람형 리깅, GLB 출력 지원을 실제 입력 형식에서 확인했다.
- 이 컴퓨터에서 Blender 5.2.1 LTS 실행 파일과 버전 응답은 확인했다. 모델 보정·리깅·렌더링·내보내기 작업은 아직 수행하지 않았다.

- 자동 안전 검토 결과: 이 특정 이미지의 외부 전송에 대한 명시적 사용자 승인이 필요하여 업로드가 거절되었다. 다른 도구·계정·직접 API 등으로 우회하지 않았다.
- 2026-09-17 공개 요금 조회: 이미지 편집 $0.15/장, Meshy 기본 생성 $0.80/회. 리깅 등 옵션이 포함된 최종 청구 총액을 확정한 것은 아니다. 승인 후 첫 시도는 이미지 1장과 3D 모델 1개로 제한하며, 재생성은 품질과 비용 확인 후 결정한다.
- 승인 전에는 모델 제출, 앱의 기존 캐릭터 교체, 생성 완료 표시는 하지 않는다.

## 완료 판정

세 모션의 영상을 보는 것만으로 끝내지 않는다. 캐릭터 외형 승인, 세 동작과 손·소품 접촉 확인, iOS/Android GLB 로딩·재생, 서버 성공/거부/응답 유실, AR 추적 손실과 백그라운드, 모션 건너뛰기, 성능을 확인해야 앱에 통합한 것으로 본다.
