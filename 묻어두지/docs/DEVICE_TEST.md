# 아이폰 기능 검증 체크리스트

실행 전 `npm run server`, `npm start`를 켜고 `npm run ios`로 개발 앱을 설치한다. 같은 Wi-Fi, 자동 날짜/시간, 정확한 위치, 카메라 권한이 필요하다. 녹음 시에는 마이크 권한도 요청한다. 음성·영상 모듈을 추가했으므로 기존 개발 앱은 재빌드한다. 앱을 사용하며 설정해야 하는 기기 신뢰/개발자 모드/서명은 사용자가 직접 완료한다.

## 1. 첫 번째 성공 경로

1. 지도 상단 `설정(실험실) → 연결 확인`에서 서버 응답을 확인한다.
2. `실제 위치 확인`에서 오차 25m 이하인지 확인한다. 안 되면 하늘이 보이는 곳으로 이동한다.
3. 지도로 돌아와 오른쪽 `캡슐 묻기`를 누른다. 캡슐 그림 → `편지 넣기`에서 테스트 편지를 쓴다. 완료 후 캡슐을 다시 눌러 `사진 넣기`에서 테스트 사진 1장을 고른다. 담긴 항목 표시를 눌러 각각 수정/빼기 화면으로 돌아갈 수 있어야 한다.
4. 개봉 시간을 **15초** 또는 **1분**으로 정한다.
5. `현재 장소에서 AR로 묻기`를 누른다.
6. 밝은 곳에서 휴대폰을 천천히 움직여 하늘색 바닥이 나타나는지 확인한다.
7. 바닥을 누르고 캡슐이 나타나면 `여기에 봉인하기`를 누른다.
8. 봉인 후 편지/사진 미리보기가 사라지고 이름·장소·개봉일만 남는지 확인한다.
9. 시간이 지난 뒤 같은 장소에서 `AR로 꺼내기`를 누른다.
10. 바닥을 다시 선택하고 `캡슐 열기`를 눌러 원본 편지/사진이 일치하는지 확인한다.

## 2. 차단·복구 경로

| 시나리오 | 기대 결과 |
| --- | --- |
| 개봉 시간 전 시도 | 남은 시간 안내, 내용 미전달 |
| 묻은 위치에서 50m보다 멀리 이동 | 거리 안내, 개봉 거부 |
| 위치 권한 거부/정확한 위치 끄기 | 안내 또는 오차 거부, 자동 우회 없음 |
| 카메라 권한 거부 | 설정 안내, 봉인/개봉 버튼 실행 안 됨 |
| 평면 인식 전/추적 상실 | AR 액션 비활성화 |
| 서버 끈 상태로 개봉 | 연결 실패, 내용 미전달 |
| 봉인 요청 직후 Wi-Fi 끊기 | 작성 내용 숨김 유지; 재연결 후 상태 확인으로 캡슐 1개만 남음 |
| 개봉 버튼 직후 앱을 백그라운드로 보내기 | 늦은 응답으로 내용 화면이 다시 열리지 않음 |
| 개봉 화면에서 앱을 백그라운드로 보내기 | 돌아오면 내용 대신 캡슐 상세 화면 |
| 앱/서버 재시작 | 내 캡슐 메타데이터 유지 |
| 웹에서 AR 봉인 시도 | 실기기 개발 빌드 안내, 실제 봉인 없음 |

위치 거리 판정은 센서 측정값 기준이다. 반경 가장자리만으로 성공/실패를 판단하지 말고, 충분히 가까운 지점과 충분히 먼 지점에서 각각 확인한다. 도로·출입 금지 구역으로 이동하며 테스트하지 않는다.

## 3. 음성·영상

작성 화면의 캡슐 → `음성 넣기` 또는 `영상 넣기`로 전용 창을 연다. 완료/닫기 후 캡슐 아래 담긴 항목으로 다시 열 수 있어야 한다. 편지 창은 키보드를 띄운 상태에서도 완료·닫기에 접근할 수 있는지 실제 아이폰에서 확인한다.

1. 새 캡슐에 짧은 테스트 목소리를 녹음하고 중지 후 미리 듣는다. 녹음 중에는 봉인 버튼이 비활성화되어야 한다.
2. 60초에 자동으로 녹음이 끝나고 첨부되는지, 취소·화면 이탈·백그라운드 전환 시 마이크가 꺼지는지 확인한다.
3. 마이크 권한 거부 시 안내가 나오고 파일 선택은 계속 가능한지 확인한다.
4. M4A·MP3·WAV를 각각 선택해 미리 듣고, 다른 파일로 교체/빼기가 되는지 확인한다.
5. 짧은 MP4와 MOV를 선택해 영상·소리를 확인한다. 무음 영상도 정상적으로 담을 수 있어야 한다.
6. 음성만, 영상만, 사진·편지·음성·영상 모두 담은 캡슐을 각각 15초로 봉인한다.
7. 봉인 전 재생 중 AR로 이동하면 재생이 멈추고, 봉인 후 파일명·재생 버튼·미리보기가 사라져야 한다.
8. 개봉 조건을 통과한 뒤 음성·영상이 원본대로 재생되는지 확인한다. 개봉 화면 이탈/백그라운드 전환 시 재생이 멈춰야 한다.
9. 음성 10MB 초과/영상 25MB 초과 파일, 지원하지 않는 확장자는 선택 후 명확한 오류가 나오는지 확인한다.
10. 큰 첨부 파일 업로드 중 연결을 끊었다가 복구해도 내용 숨김이 유지되고 캡슐이 중복 생성되지 않아야 한다.
11. 음성 창에서 녹음 준비 중/녹음 중/저장 중에 닫기 또는 다른 내용 고르기를 누르면 녹음이 취소되고 늦은 완료가 새 초안을 덮어쓰지 않아야 한다. 기존에 담아 둔 다른 자료는 유지한다.
12. 사진·음성·영상 선택 취소나 오류는 해당 창 안에서 처리하고, 선택·재생한 뒤 창을 닫으면 재생이 멈춰야 한다. 창을 다시 열면 담긴 파일은 유지돼야 한다.

기기 모델·OS 버전과 테스트 파일의 형식/코덱/크기를 함께 기록한다. 브라우저 파일 선택·재생 성공은 native 녹음/재생 검증을 대신하지 않는다.

## 4. 공동 캡슐 — 독립된 아이폰 3대로 확인

1. 세 기기에 개발 앱을 설치하고 같은 테스트 API에 연결한다. 각 설치는 서로 다른 기기 세션이어야 한다. 세 사람의 카메라·위치 권한을 먼저 확인한다.
2. 만든 사람은 `함께 묻기`에서 자신의 이름, 모임 이름, 전체 인원 3명을 입력해 초대 코드를 만든다. 나머지 두 기기는 각자 이름과 코드를 입력해 참여한다.
3. 1/3명·2/3명 상태에서는 ‘이 모임의 캡슐 담기’가 비활성화되고, 3/3명에서 만든 사람만 작성할 수 있는지 확인한다. 참여자는 봉인 버튼 대신 안내가 보여야 한다.
4. 만든 사람이 테스트 편지·사진·음성·영상을 함께 담고 15초 또는 1분을 선택해 현장 AR로 봉인한다. 이 단계에는 만든 사람만 현장에 있어도 된다.
5. 모든 기기에서 해당 캡슐의 이름·장소·인원은 보이지만 내용·파일명은 보이지 않는지 확인한다. 봉인 후 초대 코드로 새로운 기기/인원을 넣거나 명단을 바꾸는 경로가 없어야 한다.
6. 개봉 시각 전에 세 기기 모두 현장에서 ‘함께 열기 참여’를 눌러도 내용이 열리지 않아야 한다.
7. 시각이 지난 후 두 기기만 참여하면 2/3명이며 개봉이 차단되는지 확인한다. 세 번째 기기가 참여하면 다음 갱신에서 3/3명이 되고, 각 기기에서 AR 캡슐을 꺼내 원래 네 종류 내용을 확인한다.
8. 한 기기에서 ‘참석 확인 그만하기’, 뒤로 가기 또는 백그라운드 전환을 하면 나머지 기기의 다음 확인에서 인원이 감소하고, 개봉 요청이 차단되거나 열린 내용이 닫혀야 한다.
9. 한 기기의 네트워크를 끊으면 서버가 마지막 갱신을 받은 뒤 20초가 지나 참석에서 제외되어야 한다. 서버의 상태 변화가 나머지 화면에 나타나기까지 다음 갱신 및 통신 지연이 추가될 수 있다.
10. 안전한 먼 장소로 이동한 기기의 새 위치가 전달되면 해당 참석이 무효화되고 다른 기기에서도 개봉되지 않는지 확인한다. 다시 돌아와 전원이 참여하면 다시 열려야 한다.
11. 서버 재시작 후 캡슐·참여자 명단은 유지되지만 참석은 초기화되는지 확인한다. 세 기기 모두 다시 참여해야 한다.
12. 모임에 속하지 않은 네 번째 세션은 목록/참석/개봉에 접근할 수 없어야 한다. 한 기기에서 참여 이름만 바꿔 재참여해도 인원이 늘어나지 않아야 한다.

카메라/위치 권한 안내로 앱이 비활성화되면 참석이 종료될 수 있다. AR 화면을 닫고 다시 참여한다. 실제 위치가 아닌 합성 좌표로 수행한 서버 검사는 이 현장 체크리스트의 통과로 세지 않는다. 이 버전은 기기 세션 기반이며 사람 본인 확인이나 GPS 위조 방지의 완전한 검증은 범위 밖이다.

## 5. 기록할 항목

지도 홈도 실기기에서 함께 확인한다: 첫 화면 지도, 위치 권한 요청 전 기본 위치 안내, 현재 위치 버튼으로 일회성 측정, 지도 이동/확대, 캡슐 핀 선택, 하단 서랍 손잡이 탭/드래그, 목록 내부 스크롤과 상태 필터, 작성/상세에서 뒤로 갈 때 지도 복귀. 서랍 드래그와 지도 이동이 서로 간섭하지 않고 출처 표시가 가려지지 않아야 한다. 지도를 멀리 옮겨도 봉인 위치가 바뀌거나 개봉 조건이 우회되면 안 된다.

둥둥 캡슐 표시도 확인한다: 저장 위치에 바닥 타원이 고정되고 캡슐만 부드럽게 위아래로 움직이는지, 제목 위젯과 `일·시간·분·초`가 잘리지 않고 매초 갱신되는지 확인한다. 15초 테스트 캡슐이 0초 후 ‘열어볼 시간!’으로 바뀌어도 먼 장소/N−1명에서는 내용이 열리면 안 된다. 설정 → 손쉬운 사용 → 동작 줄이기에서 모션은 멈추고 카운트다운은 계속 갱신되어야 한다. 다른 화면/백그라운드에서 모션이 쉬고, 복귀하면 실제 경과 시간이 반영되어야 한다. 여러 캡슐의 색/제목이 섞이지 않는지와 확대·선택 중 깜빡임도 확인한다. 같은 좌표는 목록에서 선택하며 자동 묶음은 미구현이다. Android 지도 마커는 별도의 비트맵 갱신 경로를 사용하므로 움직임/프레임/카운트다운을 별도 실기기 검사한다.

쿼터뷰 추가 확인: 첫 진입에서 실제 카메라가 기울어지는지, 확대/지도 이동/현재 위치 복귀 후에도 캡슐 바닥점이 원래 위치와 일치하는지 확인한다. `2D`는 북향 평면, `3D`는 기본 기울기·대각 방향으로 돌아가야 한다. 마커의 제목/타이머는 기울이지 않고 읽을 수 있어야 하며 오른쪽 새 버튼이 지도/서랍 조작을 가리면 안 된다. iOS MapKit의 기기별 pitch/altitude와 Android의 지도 카메라는 웹과 다른 엔진이므로 실제 설치 후 확인한다.

- 기기 모델 / iOS 버전 / 앱 빌드
- 실외·실내 / 조명 / 바닥 재질
- 측정 위치 오차 / 서버가 표시한 거리
- 평면 인식 성공 여부와 걸린 시간
- 사진/편지/음성/영상 내용 일치 여부, 녹음과 재생 결과
- 차단/복구 케이스의 성공 여부
- 공동 캡슐의 전체 인원, 2/3명 차단·3/3명 개봉, 이탈 반영 시간, 서버 재시작 후 재참여 결과

AR 배치는 현재 세션의 바닥을 사용한다. 묻었던 바닥의 정확한 위치가 다시 인식되는지 검사하는 테스트는 현재 범위가 아니다.
