# 기능 검증 기록

이 기록은 개발 Mac에서 수행한 결과와 아직 수행하지 못한 실기기 테스트를 구분한다. 최신 검증일: 2026-09-17.

## 2026-09-17 — 포켓몬고를 참고한 쿼터뷰 시점

- 기본 pitch 55°, bearing −28°의 실제 카메라 원근 표현을 적용했다. 웹은 Leaflet에서 MapLibre GL JS 6.10.0으로 전환했고 네이티브는 기존 지도 카메라를 사용한다. 캡슐/타이머는 viewport 정렬, 현재 위치 범위는 지리 좌표로 그린다. 오른쪽 2D/3D 전환, 서랍/작성/상세 동선과 개봉 조건은 유지된다. 실제 건물 높이/고도 데이터나 포켓몬고 그래픽은 추가하지 않았다.
- `npm run check`: 타입 검사와 **72/72 통과**. 기존 66개 및 카메라/북향 평면 전환/64분할 정확도 다각형/미터 단위 반경/500m 제한/0m 처리 검사 6개. 의존성 정리 후 타입 검사도 재통과했다.
- `npm run export -- --output-dir dist-quarter-map --max-workers 2`: 최종 코드의 웹·iOS·Android 번들 통과. 내보낸 폴더의 `maplibre/6.10.0/`에 main/shared/worker 모듈과 라이선스가 함께 있는 것을 확인했다. 새로운 네이티브 모듈은 추가하지 않았다.
- `scripts/check-map-home.cjs`: 실제 엔진에서 pitch/bearing 확인, 평면 전환/복귀, 포인터 이동·휠 확대 후 쿼터뷰 유지, 3개 캡슐 선택, 초 단위 타이머/고정 바닥점/모션/동작 줄이기/패널 일시정지, 하단 서랍·필터·작성 진입·GPS 요청 시점·API 실패 복구 통과. 네 화면 크기에서 가로 넘침과 출처 위치 확인. 본문·봉인·개봉·참석 호출 0회, 사용자 DB 쓰기 0회, 브라우저 오류·경고 0개.
- 자동 검사는 외부 타일을 차단하고 ‘지도 대역’으로 표시한 SVG를 PNG로 변환해 사용했다. 공용 OSM 서버로 자동 이동/확대 요청을 보내지 않는다. `.build/map-home/04b-floating-capsules.png`에서 원근 지도 위의 정면 캡슐/타이머 배치를 확인했다.
- 실제 사용자 인앱 미리보기에서도 기본 서울 지역의 도로/건물이 비스듬히 원근 투영되는 것을 확인했다. 새 라이브러리 기본 CSS가 지도 높이를 덮어쓰던 문제를 수정한 후 전체 높이 렌더링을 확인했다. 실제 GPS 권한이나 사용자 캡슐 데이터는 변경하지 않았다.
- MapLibre의 구 버전 보안 경고를 확인하고 수정 버전으로 교체했다. 최종 설치 감사는 기존 moderate 10개, high/critical 0개다. 이전 Leaflet 의존성과 미사용 CSS만 제거했으며 사용자 데이터 삭제는 없다. [모듈 준비/출처/제한](MAP_RENDERING.md).

아이폰/Android의 실제 카메라 각도·줌·마커 투영·터치는 아직 미검증이다. 웹의 성공을 실기기 AR/GPS 성공으로 표현하지 않는다.

## 자동 테스트가 확인한 동작

- 목록/생성/조건 확인/봉인 복구 API에는 편지·사진·음성·영상 내용과 파일명이 없다. 이 경로는 DB에서도 미디어 본문을 읽지 않는다.
- 개봉 이전에는 요청을 거부한다. 클라이언트가 보내는 개봉 시각으로 서버 시간을 덮어쓸 수 없다.
- 정확한 개봉 시각에 가까운 최신 위치로 요청하면 원래 사진과 편지를 반환한다.
- 50m 바깥, 25m 초과 오차, 30초 초과 오래된 위치, 5초 초과 미래 위치, mock 플래그를 차단한다.
- 이미 열었거나 조건을 확인한 캡슐도 위치를 매번 다시 검사한다.
- 개인 캡슐은 다른 기기 세션으로 조회/개봉할 수 없다. 공동 캡슐은 확정된 참여자만 접근한다.
- 서버 재시작 뒤 세션/캡슐이 유지되고 원본 세션 토큰은 DB에 저장하지 않는다.
- 봉인 후 수정·삭제 API가 없고 클라이언트가 소유자·반경을 바꿀 수 없다.
- 입력 길이, 사진 형식/크기, HTTP 요청 형식/크기를 검사한다.
- 음성(M4A·MP3·WAV)만, 영상(MP4·MOV)만 봉인하고 서버 재시작 뒤 원본 바이트가 유지되는지 확인한다.
- 사진 4MB·음성 10MB·영상 25MB를 동시에 수용하고 개별 초과 크기/잘못된 MIME/손상된 컨테이너/위험한 파일명을 거부한다.
- 실제 생성한 WAV·AAC·MP3 테스트 신호와 H.264 MP4/MOV 파일을 검증한다(`server/fixtures/`). 미디어 컨테이너 검사는 모든 코덱 재생을 보장하지 않는다.
- 기존 사진/편지 SQLite DB를 손실 없이 확장하고 기존 봉인 요청 식별자도 그대로 복구한다.
- 큰 파일의 업로드 시간 때문에 신선한 봉인 위치가 만료되지 않도록 요청 도착 시점 기준을 확인한다. 개봉은 기존대로 실제 검사 시점 기준이다.
- local preview CORS와 no-store 응답을 확인한다.
- 동일 Idempotency-Key 재전송은 캡슐을 한 개만 생성한다. 좌표·개봉 시각도 원본을 유지한다.
- 같은 키로 내용을 바꾸면 거부하고, 복구 결과는 소유자의 메타데이터만 반환한다.

시간/위치는 자동 테스트에서 합성 입력과 주입한 서버 시계를 사용했다. 실제 GPS 센서 성능이나 위치 위조 불가를 입증한 결과는 아니다.

- 개봉 재생용 캐시는 화면 이탈 시 삭제를 시도하고 다음 앱 시작 시 남은 재생 캐시를 정리한다. 실기기 파일 정리/권한 거부/백그라운드 시나리오는 DEVICE_TEST에 남겼다.

해결한 환경 문제:

1. React Native prebuilt 파일 URI가 한글 폴더 경로에서 실패 → 첫 검증은 영문 폴더에서 수행. 이후 사용자 요청으로 원본을 `묻어두지`로 이동하고 iOS 빌드용 실제 영문 경로 복사본을 준비하도록 변경.
2. 시스템 Ruby 2.6의 `filter_map` 미지원 → 별도 Homebrew Ruby 3.3 사용.
3. JSON 3과 CocoaPods 의존성 충돌 → Gemfile에서 `< 3` 고정.
4. Viro Podfile이 요구하는 `RCT_NEW_ARCH_ENABLED=1` → iOS 실행 스크립트에 반영.

남은 Xcode 오류:

```text
iOS 26.1 is not installed. Please download and install the platform
from Xcode > Settings > Components.

No available simulator runtimes for platform iphonesimulator.
supportedRuntimes=[]
```

Xcode에서 iOS 구성요소를 설치한 뒤 `npm run ios:check`를 재실행해야 한다. 실제 설치는 아이폰 연결·기기 신뢰·개발자 모드·개발 서명을 준비한 후 `npm run ios`로 진행한다.

로컬 빌드 로그(버전 관리 제외): `.build/ios-setup.log`, `.build/ios-check.log`, `.build/viro-target.log`, `.build/pods-target.log`.
