# 삐라삐라삐 — PRD

문서 버전: v0.2
대상 릴리스: 앱인토스 MVP

## 1. 제품 목표

사용자가 2분 안에 지역을 선택해 익명 삐라를 날릴 수 있고, 현장 사용자가 정확한 좌표 없이 AR로 탐색해 한 사람만 획득할 수 있는 제품을 만든다.

## 2. 성공 기준

- 새 사용자의 첫 삐라 발송 완료율 55% 이상
- 활성 지역의 24시간 내 발견률 35% 이상
- 탐색 시작 후 오류 없이 종료되는 비율 98% 이상
- 결제 완료 주문의 이용권 지급 성공률 99.9% 이상
- 중복 지급과 중복 획득 0건
- 전체 발송 대비 신고율 1% 미만

## 3. 핵심 정책

| 항목 | MVP 정책 |
|---|---|
| 사용자 | 앱인토스 익명 식별키 기반 |
| 발송 지역 | 시·도 및 시·군·구까지만 선택 |
| 수신자 | 지정 불가 |
| 공개 위치 | 구 이름과 활성 수량 |
| 실제 위치 | 서버 전용 안전 후보 좌표 |
| 획득 | 한 삐라당 선착순 한 사람 |
| 답장 | 제공하지 않음 |
| 무료 BM | 하루 1장, 미사용분 비누적 |
| 유료 BM | 소모성 이용권 1장 300원, 이월 |
| 재배치 | 24시간 미발견 시 같은 구 안에서 최대 3회 |

## 4. 기능 요구사항

### FR-01 익명 세션

- 앱 시작 시 getAnonymousKey를 우선 사용한다.
- 원본 키는 서버에서 다시 SHA-256 처리하고 저장하지 않는다.
- 일반 브라우저 개발 환경에서는 로컬 키를 사용한다.

수용 기준:

- 동일 익명키로 재진입하면 보유 장수와 기록이 유지된다.
- 키 누락 또는 비정상 길이는 401 오류로 거절한다.

### FR-02 지역 목록

- 지역은 시·도, 시·군·구, 상태, 대표 중심점, 안전 후보점을 가진다.
- 클라이언트에는 실제 안전 후보점을 반환하지 않는다.
- 시·도 탭과 구 카드에 활성 삐라 개수를 표시한다.

수용 기준:

- 일시 중지 지역에서는 발송과 탐색 버튼이 비활성화된다.
- 정확한 낙하 좌표를 API 응답과 화면에서 확인할 수 없다.

### FR-03 이용권 지갑

- 매일 한국 시간 기준 무료 사용 가능 여부를 계산한다.
- 무료 1장은 누적하지 않는다.
- 구매 장수는 별도 잔액으로 영속 저장한다.
- 발송 트랜잭션에서 무료 장수를 먼저 소진한다.

수용 기준:

- 같은 날 첫 발송은 무료다.
- 같은 날 두 번째 발송은 구매 잔액이 없으면 402 NO_FLYER_CREDIT을 반환한다.
- 다음 한국 날짜가 되면 무료 1장이 다시 표시된다.

### FR-04 인앱결제

- SKU “ppira_single_300”을 앱인토스 콘솔의 300원 소모품으로 등록한다.
- 상품 지급 콜백에서 파트너 서버에 orderId와 SKU를 전달한다.
- 파트너 서버는 mTLS 주문 상태 API로 PAYMENT_COMPLETED 또는 PURCHASED 상태와 SKU를 검증한다.
- 주문 ID는 전역 유일하며 같은 주문 재처리 시 중복 지급하지 않는다.
- getPendingOrders와 completeProductGrant로 미결 주문을 복구한다.

수용 기준:

- 결제 취소 시 잔액이 변하지 않는다.
- 서버 지급 실패 후 재실행하면 주문을 복원할 수 있다.
- 로컬 시뮬레이션은 개발 환경에서만 허용한다.

### FR-05 삐라 작성과 발송

- 필수값: 지역, 본문, 운영정책 동의
- 선택값: 감정 태그
- 본문 길이: 1~500자
- 승인 후 이용권 1장 소진과 삐라 생성은 같은 트랜잭션에서 처리한다.

수용 기준:

- 잔액 소진과 생성 중 하나라도 실패하면 둘 다 롤백된다.
- 사용자는 자신이 발송한 삐라를 직접 획득할 수 없다.

### FR-06 콘텐츠 검수

- 연락처, URL, 이메일, SNS, 만남·거래, 협박, 정치 선전, 광고, 구체적 주소를 기본 규칙으로 차단한다.
- 공개 베타 전 외부 유해 콘텐츠 분류기와 운영자 콘솔을 연결한다.

### FR-07 비행과 낙하

- 운영 비행시간 기본값은 30분~2시간 무작위다.
- 낙하는 사용자가 선택한 구의 ACTIVE 안전 후보점 중 하나다.
- 지역 재고 한도를 넘으면 비행 상태를 유지한다.

### FR-08 AR 탐색

- 탐색 세션은 30분간 유효하다.
- 위치 정확도가 50m보다 나쁘면 획득 판정을 하지 않는다.
- 실제 낙하 지점 40m 이내에서만 2분짜리 발견 증표를 발급한다.
- 카메라 권한 거부 시 재시도 방법을 안내한다.

### FR-09 선착순 획득

- 데이터베이스 쓰기 잠금과 flyer_id UNIQUE 제약으로 한 사람만 획득한다.
- 먼저 획득된 삐라는 즉시 지역 재고에서 제외한다.
- 경쟁에서 진 사용자에게 다른 사용자가 먼저 발견했다는 메시지를 표시한다.

### FR-10 보관함과 신고

- 발신자는 상태, 대상 지역, 낙하 횟수, 발견 여부를 확인한다.
- 획득자는 본문과 획득 지역을 다시 볼 수 있다.
- 획득자만 신고할 수 있고 신고 즉시 HIDDEN으로 바꾼다.

## 5. 상태 모델

FLYING → LANDED → CLAIMED

LANDED → RELOCATING → LANDED

LANDED → EXPIRED

LANDED 또는 CLAIMED → HIDDEN → REMOVED

## 6. 비기능 요구사항

- API p95 응답시간: 일반 조회 500ms 이하, 획득 1초 이하
- 가용성 목표: 월 99.5%
- 모든 쓰기 API는 요청 ID와 감사 로그를 남길 수 있어야 한다.
- 본문은 AES-256-GCM으로 암호화한다.
- 결제 인증서와 암호화 키는 KMS 또는 비밀 저장소에서 관리한다.
- 위치 원본은 획득 판정 후 장기 보관하지 않는다.
- 본문과 정확한 좌표가 같은 운영 화면에 동시에 노출되지 않도록 권한을 분리한다.

## 8. 출시 차단 조건

- 중복 획득 또는 중복 결제 지급이 재현됨
- 운영 빌드에서 시뮬레이션 엔드포인트가 활성화됨
- mTLS 검증 없이 구매 이용권이 지급됨
- 정확한 낙하 좌표가 클라이언트에 노출됨
- 신고 접수 후 콘텐츠가 계속 노출됨
- 안전 후보점의 현장 검수와 운영 중지 절차가 없음
