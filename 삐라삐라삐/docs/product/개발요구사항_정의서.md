# 삐라삐라삐 — 개발요구사항 정의서

문서 버전: v0.2
대상: 앱인토스 비게임 MVP

## 1. 시스템 구성

| 영역 | MVP 구현 | 운영 권장 |
|---|---|---|
| 미니앱 | React 18, Vite, TypeScript | 동일 |
| 앱 브리지 | 앱인토스 WebView SDK 2.x | 최신 호환 버전 유지 |
| API | Node.js 22 HTTP 서버 | 컨테이너와 오토스케일 |
| 데이터베이스 | Node 내장 SQLite | PostgreSQL/PostGIS |
| 인증 | getAnonymousKey | 서버 익명키 검증 또는 토스 로그인 |
| 결제 | IAP 일회성 소모품 | mTLS 상태 조회와 환불 동기화 |
| 암호화 | AES-256-GCM | KMS 키 관리 |

## 2. 클라이언트 요구사항

### APP-01 초기화

- 익명 식별키 발급 후 세션 생성
- 지역, 내 삐라, 획득 삐라, 이용권을 병렬 조회
- 실패 시 사용자가 이해할 수 있는 토스트 제공

### APP-02 홈

- 전체 활성 삐라 수와 시·도 탭 표시
- 선택 도시의 구별 활성 수량 표시
- 정확한 좌표·거리·방향은 표시하지 않음
- 이용권 총 잔액과 오늘 무료 여부 표시

### APP-03 작성

- 시·도와 구를 순서대로 선택
- 본문 500자 제한과 감정 태그
- 제한 콘텐츠 안내 및 운영정책 동의
- 이용권이 없으면 결제 화면으로 이동
- 발송 완료 후 선택한 구를 명시

### APP-04 결제

- IAP.getProductItemList로 콘솔 상품을 확인할 수 있도록 확장 가능
- IAP.createOneTimePurchaseOrder 호출
- processProductGrant에서 서버 지급 API 완료 후 true 반환
- onEvent와 onError 모두 cleanup 호출
- getPendingOrders로 미결 주문을 조회하고 지급 후 completeProductGrant 호출
- 취소·실패·지급 실패 메시지를 구분

### APP-05 탐색

- 탐색 전 세 가지 안전 안내
- 운영 환경에서 후면 카메라 실시간 미리보기
- 앱인토스 openCamera 폴백
- 위치 확인 후 서버 스캔
- 개발 환경에서만 체험 위치 버튼 표시

### APP-06 접근성

- 모든 버튼에 읽을 수 있는 텍스트 또는 aria-label 제공
- 색상만으로 상태를 전달하지 않음
- prefers-reduced-motion 대응
- 최소 터치 영역 40px 이상

## 3. API 요구사항

### 공개 조회

- POST /v1/session
- GET /v1/regions

### 인증 조회와 쓰기

- GET /v1/wallet
- POST /v1/purchases/grant
- POST /v1/flyers
- GET /v1/me/flyers
- GET /v1/found-flyers
- POST /v1/hunts
- POST /v1/hunts/:id/scan
- POST /v1/claims
- POST /v1/found-flyers/:id/reports

모든 인증 API는 X-User-Key 헤더를 요구한다. 운영에서는 원본 키의 유효성을 서버에서 검증한 뒤 내부 사용자 ID로 변환한다.

## 4. 데이터 요구사항

### users

- id: 해시 사용자 ID
- purchased_credits: 유료 잔액, 0 이상
- created_at

### daily_free_usage

- user_id와 한국 날짜 복합 기본키
- 사용된 flyer_id와 used_at
- 한 날짜에 한 번만 삽입되어야 함

### purchases

- order_id 전역 기본키
- user_id, sku, quantity, amount_krw
- status: VERIFIED, SIMULATED, REFUNDED
- 동일 order_id 재호출은 잔액을 추가하지 않음

### regions

- city, district, 대표 중심점
- status, inventory_cap
- search_points_json은 MVP 전용이며 운영에서 PostGIS 안전 다각형으로 교체

### flyers

- sender_user_id, target_region_id
- 암호화 본문, 길이, 감정 태그
- credit_source: DAILY_FREE, PURCHASED, SEED
- 상태와 생성·비행·획득 시각

### flyer_landings

- flyer_id, sequence, region_id
- 서버 전용 목표 좌표와 획득 반경
- landed_at, expires_at, status

### claims

- flyer_id UNIQUE
- claimant_user_id와 landing_id
- 획득 시각과 위치 정확도 구간

## 5. 트랜잭션 규칙

### 발송

1. 쓰기 잠금 시작
2. 오늘 무료 사용 행 삽입 시도
3. 이미 사용했다면 purchased_credits 조건부 차감
4. 잔액이 없으면 전체 롤백
5. 삐라 생성
6. 커밋

### 결제 지급

1. mTLS로 orderId, SKU, 상태 검증
2. 쓰기 잠금 시작
3. purchases에 order_id 삽입
4. 이미 존재하면 현재 지갑 반환
5. purchased_credits 1 증가
6. 커밋

### 획득

1. 발견 증표 해시와 만료 확인
2. sender와 claimant가 다른지 확인
3. claims 삽입
4. flyers와 landing 상태 변경
5. UNIQUE 충돌은 FLYER_ALREADY_CLAIMED로 변환

## 6. 보안 요구사항

- TLS 1.2 이상
- IAP 인증서 파일을 이미지나 저장소에 포함하지 않음
- 원본 익명키, 본문, 정확한 위치를 로그에 기록하지 않음
- 본문 암호화 키는 환경별 분리 및 정기 교체
- 구매 지급 API 속도 제한과 주문 감사 로그
- 운영 시뮬레이션 플래그 강제 비활성화
- 운영자 권한을 콘텐츠 검수와 위치 관리로 분리

## 7. 운영 배치

- 1분마다 비행 완료 삐라 낙하
- 5분마다 만료 낙하 재배치
- 매일 결제 완료·환불 주문 대사
- 매일 지갑 음수, 중복 주문, 고아 주문 무결성 검사
- 지역별 재고 한도와 신고 급증 모니터링

## 8. 테스트 요구사항

- 연락처, 정치 선전, 협박 문구 차단
- 하루 무료 1장과 날짜 전환
- 무료 우선 및 유료 잔액 차감
- 동일 주문 멱등 지급
- 선택 구 밖 낙하 금지
- 두 사용자의 동시 획득 경쟁
- 위치 정확도 부족
- 결제 취소, 서버 지급 실패, 미결 주문 복원
- 운영 플래그에서 로컬 시뮬레이션 차단
