# 승부예측 프로그램 — Claude 작업 지침

이 폴더는 베트맨 프로토 승부식(축구·야구·배구·농구, 핸디캡 포함) 조합과 축구토토 승무패 예측을 위한 작업 공간이다. 답변은 한국어로 한다.

## 최종 목표 (사용자 명시, 2026-10-06): 베트맨 토토 배팅으로 수익 창출
- 적중률·분석 스킬·회고는 전부 이 목표의 수단이다. 보고할 때 '적중'과 '수익(ROI)'을 항상 구분한다.
- 수익은 기대값(공정 확률 × 베트맨 배당)이 1.0을 넘는 가격에서만 나온다. 베트맨 환급률은 프로토 약 88%, 토토 50%라 평균 선택지는 손해다.
- 그래서 모든 분석은 "어디서 1.0 넘는 가격이 나오는가"로 수렴시킨다. 가설: (1) 베트맨이 직접 매기는 정수 핸디캡·언더오버 가격 오류, (2) 결장·라인업 뉴스 반영 지연(킥오프 1~3시간 전 재스캔), (3) 풀 상품의 대중 편향(승무패 이월 회차, 매치 비인기 스코어).
- 판정 근거는 `tracker.py report`의 기대값 구간별·유형별·근거별 ROI 표다. 표본 300개 전에는 결론을 내리지 않는다.
**작업을 시작하면 항상 이 파일 → `분석방법론.md` → `분석규칙.md` → 해당 팀의 `팀노트/<팀명>.md` → 최근 `회차별분석/` 순서로 읽는다.**

## 모드 1. 예측 (사용자가 경기 목록을 보냈을 때)

### 1) 정보 검색 (경기마다 WebSearch 필수, 추측 금지)
- 부상자·결장자·징계, 예상 선발 명단. 야구는 선발투수를 반드시 확인한다. 배당이 이미 움직였으면 반영된 것으로 보고, 아직 안 움직인 결장·로테이션 소식만 확률에 쓴다. 결장 여부가 불확실한 경기는 '뉴스 위험'으로 표시해 복수 마킹 후보로 올린다.
- 최근 5경기 폼, 득실점, 가능하면 xG.
- 홈/원정 성적, 맞대결 전적.
- 일정 피로도: 연전, 주중 대항전·컵대회, 이동 거리, 휴식일.
- 동기부여: 우승·진출·강등권 경쟁, 순위 확정 여부.
- 감독 교체, 내부 이슈 등 최신 뉴스.
- 경기장과 날씨. 야구는 구장 특성, 바람, 우천을 본다.
- 배당률을 찾을 수 있으면 시장 확률과 비교한다.

### 2) 확률 산출 (`분석방법론.md` 순서대로)
1. 시장 기준선: 배당(가능하면 Pinnacle, 최신 값) → `python3 scripts/devig.py 홈 무 원정` (Shin 값 사용)
2. 모델: `python3 scripts/match_model.py --xg 홈xG 홈xGA 원정xG 원정xGA --games N --league 리그평균득점 --market 시장% --w 0.9`
   - xG가 홈/원정 분리 수치면 `--split`을 붙인다. `--blend log` 결과도 비교용으로 확인한다.
3. 뉴스 보정: 시장에 아직 반영 안 된 정보만 반영하고, 보정폭은 분석규칙의 범위를 따른다.
4. 무승부 체크리스트를 확인한다.
- 경기마다 승/무/패 확률(합계 100%)을 낸다.
- `분석규칙.md`의 보정 규칙을 적용하고, 어떤 규칙을 적용했는지 기록한다.
- 축구 무승부를 과소평가하지 않는다. 전력이 비슷하면 보통 25~32%다. 단, 배당이 있으면 시장의 무승부 확률을 그대로 쓴다(백테스트에서 가산 효과 없음).
- 배당률 역산 확률과 차이가 크면 근거를 명시한다.

### 3) 마킹 구성 (승무패는 최대 4조합, 2026-10-01부터)
- 사용자 결정(2026-10-01): 승무패는 전부 적중 확률이 매우 낮으므로 **최대 4조합(4,000원)** 까지만 추천한다. `combo_optimizer.py <입력.json> --max 4`로 1조합(전부 최다확률)과 4조합(박빙 2경기 복수)을 함께 보여 준다. 무승부 후보는 Pinnacle 총합 라인으로 기대득점을 역산해 무 확률이 높은 경기 순으로 고른다(57회 분석 참고). 아래 100조합 규칙은 명시적으로 요청할 때만 쓴다.
- 조합 수는 경기별 선택 개수를 모두 곱한 값이다. 100은 상한일 뿐 목표가 아니다.
- `python3 scripts/combo_optimizer.py <입력.json>`으로 계산한다. 입력 형식은 스크립트 상단 주석을 참고한다.
- 결정 규칙: 모든 경기를 단일로 두고 시작한다. 조합 증가 대비 적중 확률 증가 효율이 가장 큰 확장부터 적용한다.
- 멈추는 조건:
  - 다음 확장을 하면 100조합을 넘는다.
  - 복수 확장 배수가 1.4 미만이다(2순위가 1순위의 40% 미만).
  - 전체 확장 배수가 1.25 미만이다.
- 그래서 30조합 이하가 될 수도 있다. 구성 이유를 한 줄로 설명한다.

- 대중 투표율을 알면 입력 JSON에 "투표"를 넣어 인기도 대비 가치를 확인한다. 가치 1.2 이상인 선택지는 복수 마킹의 두 번째 선택으로 우선 고려한다.

### 3-0) 적중 확률 최대화 절차 (2026-10-02부터 기본, 사용자 목표: 가장 잘 맞히기)
근거: `분석규칙.md` "적중 확률 극대화 규칙", `분석방법론.md` 7장.
0. **사용자 결정(2026-10-02): 베트맨 배당 1.3 미만 선택지는 단식·조합 어디에도 추천하지 않는다.** 스캐너 기본값 `--min-odds 1.3`이 자동으로 뺀다.
1. `python3 scripts/odds_scan.py --best` — 경기마다 일반·핸디캡·언더오버 전체에서 확률이 가장 높은 선택지 1개를 확률 순으로 본다. `*` = 역산 모델 값.
2. 상위 선택지마다 뉴스 위험(선발 미정, 부상 복귀, 우승 확정 후 휴식, 친선전 대거 교체)을 WebSearch로 확인하고, 위험하면 다음 순위로 내린다. 확률을 직접 고치지는 않는다(시장이 더 정확).
3. 조합은 `--target 배당`(목표 배당 중 적중 최대) 또는 `--combo N`. 사용자에게 목표 배당·경기 수를 묻는다.
4. **사기 직전(킥오프 1~3시간 안) 다시 돌린다.** 마감에 가까운 배당일수록 정확하다(오픈 대비 유의).
5. 예측기록.csv에 고른 선택지와 확률을 남겨, 종목별(특히 야구·배구·농구) 실제 적중을 누적 검증한다.

### 3-1) 프로토 승부식 단식 모드 (2026-09-30부터 기본)
**먼저 `python3 scripts/odds_scan.py`를 돌린다.** 베트맨 프로토 배당 전체를 Pinnacle 공정 확률과 비교해 기대값을 매긴다.
- 기대값 1.0 미만인 경기는 돈 목적이면 사지 않는다. 심층 분석은 기대값 0.95 이상인 경기에만 쓴다(분석으로 시장을 뒤집는 게 아니라, 베트맨이 늦게 고친 배당인지 확인하는 용도).
- 매칭 실패 경기는 `--all`로 보고 `data/team_names.json`에 한글→영문 팀명을 추가한다.
- 회차·종목별 보기 (2026-10-02 추가):
  - `--no-draw --prob`: 야구·배구·농구만, 경기당 유력한 쪽 한 줄을 이길 확률(Pinnacle 공정확률) 순으로.
  - `--sports 배구` / `--round 118` / `--min-prob 60`: 종목·회차·확률 하한 필터. 이미 시작한 경기는 기본 숨김(`--started`).
  - 출력 맨 위 "배당 미발표·대진 미정" 목록은 베트맨이 0.0으로 올려 둔 경기다. 배당이 뜨면(보통 전날) 다시 돌린다.
  - 무승부 없는 종목은 적중률이 높지만 배당도 그만큼 낮다. 베트맨 환급률(약 88%)은 종목과 무관하므로 '무 없음'이 수익상 유리하지는 않다. 적중률을 원하면 `--prob`, 돈 목적이면 기대값으로 본다.
사용자는 승무패(14경기) 대신 **프로토 승부식**으로 산다. 2026-10-02부터는 회차마다 한 번, 이길 확률 높은 경기를 묶은 조합으로 산다(아래 참고). 승무패 14경기 조합 마킹은 요청할 때만 낸다.
- 베트맨 프로토 회차의 해당 경기 배당을 가져와 경기마다 `기대값 = 최종 확률 × 배당`을 계산한다 (`scripts/devig.py`로 베트맨 시장 확률도 같이 표기).
- 추천 기준: 최종 확률 60% 이상이고 기대값 0.85 이상인 단식만. 승리 확률 순으로 3~5개.
- ~~2경기 이상 묶는 조합은 권하지 않는다~~ → **2026-10-02 사용자 결정: 반복 단식이 아니라 회차마다 한 번씩 조합으로 산다. 이길 확률 높은 경기를 묶는 방식.**
  - `python3 scripts/odds_scan.py --no-draw --combo 3`: 3경기 조합을 적중 확률 순으로 (경기당 유력한 쪽만 후보).
  - `--target 3`: 합계 배당 3배 이상 조합(2~5경기) 중 적중 확률이 가장 높은 것. `--min-prob 65`로 후보를 좁힌다.
  - 조합 기대값이 (약 0.88)^N로 떨어진다는 점은 한 줄로만 알리고, 사용자의 조합 방식을 존중한다.
  - 핸디캡(야구 ±x.5, 배구 세트, 축구 소수·정수)도 기본으로 후보에 들어간다. 같은 경기의 일반·핸디캡은 한 조합에 같이 넣지 않는다. 빼려면 `--no-handi`.
  - 추천 순서: 원하는 배당(또는 경기 수)을 묻고 → 스캔 상위 조합 중 뉴스 위험(선발 미정, 부상 복귀, 우승 확정 후 휴식) 경기를 빼서 1~3개 제시.
- 축구 승무패형 단식은 무승부가 나오면 진다. 최종 확률 표의 '승' 값이 곧 적중 확률이다. 야구 승패형은 무승부 시 적중특례(배당 1.0).
- 회고 때 단식 기준 적중률과 수익률(ROI = 회수금/투입금)을 집계한다.

### 3-2) 축구토토 매치 (점수 맞히기, 2026-10-01 추가)
- `python3 scripts/match_scan.py`로 (전반, 최종) 441칸의 모델 확률과 대중 점유율을 비교한다. 풀 배당이라 기대값 = 0.5 × 모델/대중.
- 추천은 '묶음 안'(최종 스코어 하나 + 모순 없는 전반 후보 여러 칸, 칸당 100원)으로 낸다. 적중률 2~6%짜리 복권이라는 점을 한 줄 명시한다. 사용자 방향(2026-10-01): 점수 토토보다 핸디캡 활용 쪽을 키운다. 매치는 소액·추적용.
- 대중 점유율은 마감까지 움직이므로 마감 직전에 다시 돌린다. 대중 투표 10표 미만 칸의 배당은 신뢰하지 않는다.

### 4) 출력 형식
```
[프로토 단식 추천 — 확률 순]
1. 스페인 승  최종 85% × 배당 1.05 = 기대값 0.89  (근거 한 줄)
2. …
피하는 경기: … (확률 60% 미만 또는 기대값 0.85 미만)
뉴스 위험: …
```
(승무패 조합을 요청받았을 때만) 경기별 확률 + 총 N조합 / 전체 적중 확률 / 등위별 확률 / 구성 이유

### 5) 저장
- `회차별분석/YYYY-MM-DD_회차.md`: 경기별 상세 근거, 검색 출처 링크, 적용한 규칙, 최종 마킹.
- `예측기록.csv`: 경기마다 한 줄씩 추가한다. result 칸은 비워 둔다. 배당이 있었던 경기는 m_win, m_draw, m_lose에 시장 확률(Shin)을 적는다. 배당이 없으면 비워 둔다.

## 모드 1.5. 전체 추적 (구매·추천 여부 무관, 2026-10-06부터 매 회차 필수)
사용자 결정: "분석과 회고는 구매 여부와 상관없이 전부 해야 분석 스킬이 는다."
- 스캔은 항상 `--log`를 붙인다 (`python3 scripts/odds_scan.py --best --log`). 모든 경기·모든 유형의 선택지와 공정 확률이 `data/스캔기록.csv`에 쌓인다. 같은 선택지는 가장 늦은 스캔(킥오프에 가까운 배당)으로 덮어쓴다.
- 회차가 끝나면(또는 회고 때) `python3 scripts/tracker.py results` → 베트맨 공식 결과로 자동 채점. `python3 scripts/tracker.py report` → 확률 구간·종목·유형(일반/핸디캡/언더오버)·근거(직접/파생/모델)·기대값 구간별 예상 vs 실제와 ROI를 `회차별분석/전체추적_YYYY-MM-DD.md`에 저장.
- 판단 기준: 어떤 구간의 예상-실제 차이가 300개 이상 표본에서 ±3%p를 넘으면 그때 분석규칙에 올린다. 그 전에는 '관찰'로만 적는다.
- `예측기록.csv`는 사람이 고른 추천·구매 기록용으로 그대로 둔다. 전체 추적은 스캔기록이 담당한다.

## 모드 2. 회고 (사용자가 결과를 알려주거나 회고를 요청했을 때)
0. 먼저 `python3 scripts/tracker.py results && python3 scripts/tracker.py report`로 전체 추적을 갱신한다.
1. 결과를 받거나 검색해서 `예측기록.csv`의 result, hit 칸을 채운다. result는 홈팀 기준 `승`/`무`/`패`로만 적고(점수는 note 앞에), 그래야 calibration.py가 읽는다.
2. 틀린 경기마다 원인을 분류한다: 정보 누락 / 가중치 오판 / 무승부 과소평가 / 순수 이변.
3. 반복되는 패턴이면 `분석규칙.md`에 규칙을 추가하거나 수정한다. 근거 회차를 적고, 신뢰도는 낮음·중간·높음으로 표시한다.
4. 팀 관련 새 정보는 `팀노트/<팀명>.md`에 추가한다.
5. 5회차 이상 쌓이면 `python3 scripts/calibration.py`로 보정 상태와 시장 대비 RPS를 점검하고, 결과를 `분석규칙.md`의 "확률 보정" 섹션에 반영한다.
6. 한 번의 이변으로 규칙을 만들지 않는다. 최소 2~3번 반복된 패턴만 규칙으로 만든다.
7. 규칙을 바꾸기 전에 가능하면 `python3 scripts/backtest.py`로 과거 자료에서 먼저 검증한다 (자료 준비법은 스크립트 상단 주석).

## 공통 규칙
- 예측은 확률일 뿐이다. 대부분의 회차는 전부 적중하지 못한다는 점을 짧게 한 줄만 언급한다.
- 정보가 부족하거나 선발 명단이 미발표인 경기는 그렇다고 밝힌다.
- 파일은 기존 내용을 지우지 않고 추가·수정한다.
