# 가치 전략 운영 설계 — 회수율 1.3 유지 → 1.5 향상 (사용자 요청 2026-10-18)

> 질문: "조합 추천에 배팅 금액도 들어가야 하지 않나? 1.3 이상이 나오게 하려면 어떻게 보고해야 하고, 1.5 이상으로 올리려면 어떤 데이터를 모아 분석 스킬을 올려야 하나?"
> 답의 뼈대: **수익은 적중률이 아니라 가격에서 나온다.** 그래서 ① 가격 규칙(W2)으로 고르고 ② 금액은 '증명된 만큼만' 올리며 ③ 회수율보다 빨리 판정되는 CLV로 매일 검증하고 ④ 가격이 왜 틀렸는지 설명하는 데이터를 쌓아 규칙을 키운다.

## 0. 현재 근거 (116~123회, 채점 선택지 4,937개)
| 방식 | 회수율 |
|---|---|
| 아무거나 | 0.85 |
| 확률 높은 다리(지금까지 A/B 추천 방식) | ~0.90 — 베트맨 마진(다리당 ~12%)이 2폴더에서 곱해짐 |
| W(언더·기대값≥0.93·공정≥50%) 2폴더 | 1.27~1.43 |
| **W2(W + Pinnacle 확률 첫 스캔 대비 유지/상승)** 2폴더 | **1.53 (13장)** · 단식 학습 1.21 / 검증 1.37 |
표본이 작아 **실제 회수율은 1.0~1.5 어디든 될 수 있다** — 그래서 단계별 운영(§2)과 CLV 검증(§3)이 필요하다.

## 1. 추천(보고) 형식 — 블록마다 이 순서
```
[가치 전략 W2 · 단계: 검증 / 조합당 5,000원]
| 번호 | 경기 | 라인 | 선택 | 베트맨 | Pinnacle 공정 | 기대값 | 시장 이동(첫→지금) |
W1 = 다리1 + 다리2 = 2.31배 · 시장 적중 37% · 💰 5,000원 · 🕒 구매 HH:MM (마감 HH:MM)
구매 직전 확인: 두 다리 배당 ≥ (지금−0.05), 기대값 ≥ 0.93 — 아니면 사지 않음
누적: 채점 N조합 · 적중 k · 회수율 x.xx · 평균 CLV +y% · 최대 연패 z
```
- 분석 추천(A/B, 확률 기반)과 **따로** 보여 준다. 섞지 않는다(목적이 다름: A/B = 분석 실력 학습, W2 = 수익).
- 블록당 최대 2조합, 같은 경기 두 번 금지, 3폴더 금지(표본 생길 때까지).
- 구매하면 실제 산 배당·금액을 `구매기록.csv`(ticket 'W…')에 남긴다 → 실전 회수율.

## 2. 금액 — 증명된 만큼만 (`value_scan.py` PHASES)
| 단계 | 조건 | 조합당 | 비고 |
|---|---|---|---|
| 검증 | 채점 30조합 미만 | 5,000원 (원하면 0원 가상만) | 지금 단계 |
| 소액 실전 | 30조합+ · 회수율 1.2+ · 평균 CLV > 0 | 10,000원 | |
| 확대 | 80조합+ · 회수율 1.2+ · CLV > 0 | 20,000원 | 이후 ¼ 켈리 검토(추정 우위를 0 쪽으로 깎아서) |
| 중지 | 최근 30조합 회수율 < 0.95 또는 CLV ≤ 0 | 0원 | 원인 분석 후 재개 |
- 연패 대비: 2폴더 적중 ~45%면 5연패 확률이 약 5% — 단계 금액 × 10 정도가 한 번에 빠질 수 있는 최대치로 잡는다.
- **손실 만회 증액 금지**(기존 규칙). 금액은 단계표로만 바뀐다.
- A/B 분석 추천 금액은 기존 `budget.py`(회차 10만원) 그대로, W2와 합쳐 회차 상한을 넘기지 않는다.

## 3. 검증 지표 — 회수율보다 CLV를 먼저 본다
- **CLV** = 산 배당 × Pinnacle 마감 공정확률 − 1. 결과(운)와 상관없이 "좋은 가격에 샀는가"를 바로 보여 준다. 회수율은 수백 장이 필요하지만 CLV는 30~50장이면 방향이 나온다.
- `value_scan.py --report`가 매일 채점·CLV를 채운다(autoscan이 킥오프 75분 안에는 5분 간격으로 배당을 남기므로 마감 공정확률이 있다).
- 판정: CLV > 0 이면서 회수율 낮음 → 운(계속), CLV ≤ 0 → 규칙이 낡음(중지·재탐색).

## 4. 1.5 이상으로 올리기 위해 모을 데이터
| 데이터 | 왜 | 어떻게(현황) |
|---|---|---|
| ① 베트맨 배당 변경 시각·폭 | 베트맨이 Pinnacle을 늦게 따라오는 구간(지연)이 가치의 원천 — 언제·어느 리그에서 늦는지 | `배당이력.csv`(30분, 마감 75분 전 5분) ✔ → 리그·라인별 '지연 시간' 집계 추가 |
| ② Pinnacle 시가→마감 이동 | W2의 Δp 신호. 이동 크기·시점(라인업 발표 직후 등)별 회수율 | `배당이력` ✔ → 이동 시점 특징 추가 |
| ③ 언더 가격의 리그·라인별 편향 | 베트맨이 어느 리그·기준점(2.5/3.5)에서 언더를 후하게 매기는지 | 스캔기록 ✔ → 리그×라인 회수율 표(30장+ 리그만) |
| ④ 경기 환경 | 비·강풍·고도·이동거리 → 득점 감소 = 언더 유리 | `venue_env.py` ✔(10/17) → W2 다리에 붙여 효과 측정 |
| ⑤ 내 득점 모델(xG λ) | 가격(W2) + 내 분석(언더 확률 ≥ 시장)이 겹칠 때 더 좋은지 | 5대 리그 xG ✔, 나머지 리그 xG 수집 필요 |
| ⑥ 확정 라인업 | 주전 공격수 결장·로테이션 = 득점 감소 | `match_inputs` 라인업 ✔ → 공격수 결장 수 특징화 |
| ⑦ 실제 구매 배당·시각 | 가상과 실전의 차이(배당 변동·구매 지연) | `구매기록.csv` ✔ |
| ⑧ 다른 업체 배당(합의 가격) | Pinnacle 하나보다 정확한 '진짜 확률' | 미수집 — 수집 가능한 무료 소스 조사 필요 |
| ⑨ 득점 시간대·점수 | 0-0·1-0 비중 리그별 → 언더 기준점 선택 | 결과 수집 ✔(점수) |

## 5. 분석 스킬 향상 절차 (데이터가 쌓이면)
1. **매일**: `value_scan.py --report` — 채점·CLV·단계.
2. **매주(또는 50조합마다)**: `scripts/value_research/roi_ds.py → roi_search.py` 재탐색. 반드시 **시간 분리 검증**(앞 기간에서 찾고 뒤 기간에서 확인). 검증에서도 이기는 규칙만 채택 — 과거에 맞춘 숫자는 믿지 않는다.
3. **특징 추가 순서**(효과가 클 것 같은 순): ③ 리그×라인 → ② 이동 시점 → ④ 날씨 → ⑤ 내 xG 확률 겹침 → ⑥ 라인업. 하나씩 넣고 검증 회수율이 오르는지 본다.
4. **표본 300조합 이상**: 규칙 대신 확률 모델(로지스틱 회귀 — 적중 여부 ~ 기대값·Δp·리그·라인·날씨…)로 '진짜 확률'을 추정해 기대값 1.1+ 다리만 고르는 방식으로 전환 검토.
5. 모든 변경은 `분석규칙.md`에 [시험]→[중간]으로 기록, 근거 회차·표본 수 명시.

## 6. 하지 않을 것
- 표본 10장 안팎의 좋은 숫자(예: Δp≥1 2폴더 2.05, 3폴더 2.15)로 규칙을 바꾸지 않는다.
- 연패 중 금액을 올리지 않는다.
- 가치 전략 다리를 '확률 높아 보여서' 고르지 않는다 — 가격 조건이 먼저다.
