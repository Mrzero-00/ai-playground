# 데이터 정합성 · 근거 기록 · 수집/분석 분리 (사용자 지시 2026-10-16) — 최우선 규칙

> **지금은 분석 기술의 정확도를 키우기 위해 '자료를 쌓는 단계'다.** 잘못된 데이터(오래된 뉴스·과거 시즌 자료·리그 평균)로 분석하고
> 그 결과를 기록하면 의미 있는 자료가 쌓이지 않고, 오히려 정확도 향상을 방해한다. 시장 비교는 보조이고, 목표는 **우리 분석의 정확도**다.
> 그래서 가장 중요한 두 가지:
> 1. **데이터 정합성** — 분석에 쓰는 데이터·뉴스·팀 정보가 진짜 최신인지 확인한다.
> 2. **근거의 데이터화** — 승/무/패 확률과 추천 이유를 나중에 교육 자료로 쓸 수 있을 만큼 구조화해 남긴다.

## 0. 이 규칙이 생긴 경위 (2026-10-16, 123회)

| 오류 | 원인 | 발견 |
|---|---|---|
| 프로시노네-사수올로 언더3.5 78.9% | 경기별 xG(프로시노네 xGA 2.42) 대신 리그 평균 근처 기준선 총득점(2.4골) 사용 — xG로는 3.7골·언더 약 50% | 사용자가 근거를 물어서 |
| 언더 확률 4경기 모두 시장보다 9~24%p 과대 | 위와 같은 원인의 반복 | 사용자가 전체 확률표를 요청해서 |
| 프랑크푸르트 H-2 패 85%로 기록할 뻔 | 핸디캡 정의를 머리로 계산(2골차 승=무 누락) | 재계산 중 |
| 번리 '안 짐' 66% | 기준선이 강등팀 지난 시즌(1부) 자료에 끌렸을 가능성, 갈림 대부분이 모델 차이 | 2차 반론 |
| 123회 팀 팩트시트 미생성 | 08시 정기 작업에서 `team_facts.py` 미실행, 블록 분석이 점검 없이 진행 | 사용자 질문 후 점검 |
| (이전) 로드리 이적을 '부상'으로, 2026 감독 교체를 '오류'로 | 모델 기억(2025) 의존 | 10/14 |

→ 오늘 분석한 123회 축구 8경기는 `정합성 C`(학습 제외)로 소급 표시했다(`data/정합성기록.csv`).

## 1. 역할 분리 — 수집가 / 검사 / 분석가 (사용자 제안 2026-10-16)

```
[수집가 에이전트]  웹 검색 전담. 사실만, 날짜·URL 필수, 해석·확률 금지
        ↓  수집 JSON (경기별)
[검사 integrity.py]  날짜·출처·팩트시트·INPUTS·교차 확인 → 문제 있으면 수집가에게 재수집
        ↓
[분석가 에이전트]  웹 검색 금지. 수집 JSON + 팀노트 FACTS/INPUTS + 기준선 + xG 만으로 확률 계산
        ↓  근거 JSON (기준선 → 요인별 %p → 최종, 점수분포 λ, 결론)
[검사 integrity.py add]  합계·xG 사용·뉴스 날짜·요인 수 → 등급 A/B/C
        ↓
[pick_table]  C·미검사 = 다리 금지 / 학습 스크립트는 C 제외
```

- **왜 나누나**: 한 에이전트가 검색과 분석을 같이 하면 오래된 기사·기억을 '사실'로 섞고, 근거와 해석이 뒤엉켜 나중에 무엇이 맞았는지 배울 수 없다.
  수집가는 '무엇이 사실인가', 분석가는 '그 사실이 확률을 얼마나 움직이나'만 책임진다.
- 분석가는 수집 JSON에 없는 사실을 쓰지 않는다. 필요하면 '추가 수집 요청' 목록으로 돌려보낸다.
- 프롬프트: `조사프롬프트.md` → '수집가 프롬프트', '분석가 프롬프트'.

## 2. 데이터 정합성 규칙

| 항목 | 기준 | 위반 시 |
|---|---|---|
| 팀 팩트시트(FACTS) | 양 팀 모두 존재, 3일 이내 (`team_facts.py --round N --stale 3`) | C |
| 입력 자료(INPUTS: xG·휴식일·라인업) | 양 팀 모두 분석 당일 수집 (`match_inputs.py`) | C |
| 결장·복귀·징계·라인업·감독·선발 뉴스 | 기사 날짜·URL 필수, 분석 시점 7일 이내 | C |
| 득점 모델 | 경기별 λ. **리그 평균 금지**. Understat 5대 리그는 xG λ(공격 xG·상대 xGA 평균, 홈 보정) | C |
| 핸디캡·언더오버 확률 | 점수 분포에서 계산(수기 계산 금지) — 정의: H-1 패 = 무·원정승, H-2 패 = 홈 1골차 이하 승·무·패, H+1 승 = 홈 안 짐 | C |
| 근거 합계 | 기준선 승 + Σ요인 영향 = 최종 승 (±2%p 경미, ±4%p 초과 C) | B/C |
| 요인 수·결론 | 요인 2개 이상, 결론(추천 이유) 문장 | C |
| 기준선 표본 | 승격·강등 팀(이번 시즌 리그 경기 5경기 미만)은 '기준선 불신' 요인으로 적고 갈림 근거로 쓰지 않는다 | — |
| 출처 엇갈림 | 두 곳 이상에서 확인될 때만 '확정', 아니면 '의심' | — |

- **분석 전**: `python3 scripts/integrity.py pre <회차> --from --to` → 문제 경기가 있으면 먼저 `team_facts.py`·`match_inputs.py`를 돌리고 다시 검사. 통과 전에는 분석하지 않는다.
- **분석 후**: `python3 scripts/integrity.py add <회차> <근거.json>` → 등급이 `전체경기기록.csv` '정합성' 열에 들어간다.

## 3. 근거 기록 (교육 자료)

`data/근거기록.csv` — 경기마다 '요인' 행 여러 개 + '요약' 행 1개.

- 요인 행: 유형(결장·복귀·징계·라인업·감독·xG·폼·휴식·일정·맞대결·동기·홈원정·전술·날씨·선발투수·불펜·기타) · 팀 · 선수 · 등급(S/A/B/C) · 상태(확정/의심/추정) · **영향(홈 승 %p, + 홈 유리)** · 내용 · 출처 URL · 기사 날짜.
- 요약 행: 기준선 · 득점모델(방식·λ·출처) · 최종 확률 · 선택지별 확률과 계산 방식 · 결론 · 미확인.
- 결과 뒤 `integrity.py grade <회차>` → 요인마다 방향 적중(1/0/무/중립).
- `integrity.py report` → **요인 유형×상태별 방향 적중률**(C 제외). 이것이 '어떤 근거가 실제로 맞았나'를 배우는 교육 자료다.
  30건 이상 쌓인 유형부터 영향 크기(%p)를 조정한다(분석규칙.md에 [관찰]→[중간] 승격).

## 4. 등급과 사용

| 등급 | 뜻 | 추천 다리 | 학습(calibrate·hit_model·own_model·fast_learn) |
|---|---|---|---|
| A | 모든 검사 통과 | 가능 | 사용 |
| B | 경미한 문제만(합계 ±2~4, 비뉴스 요인 날짜 누락 등) | 가능 | 사용 |
| C | 심각한 문제(위 표) | **금지** (`pick_table` ✗ 정합성) | **제외** |
| (빈칸) | 미검사(10/16 이전 기록) | 금지 | 사용(과거 자료) |

C 경기는 자료를 고쳐 `add`를 다시 돌리면 새 등급으로 덮어쓴다. 시간이 없어 고치지 못하면 그 블록은 '추천 없음'으로 끝낸다.

## 5. 사용자에게 보여 줄 때

추천 표 아래에 다리마다 **근거 요약 2~3줄**(기준선 → 주요 요인 %p → 최종, 출처 날짜)을 붙인다. "왜 이 확률인가"를 사용자가 물어보기 전에 보여 준다.
