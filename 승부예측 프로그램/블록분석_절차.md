# 자동 루프 — 회차 감시와 마감 블록 분석 (사용자 지시 2026-10-10)

> 하루 두 번(00시·12시) 새 회차를 확인하고, 경기를 **판매 마감 시각별 블록**(첫 마감부터 60분 안에 마감되는 경기, 3경기 미만이면 90분 안 이웃 블록과 합침 — 최대한 같은 시간대끼리)으로 묶어 두었다가,
> **블록 마감 70분 전에 한 번만** 분석해서 조합을 추천한다. 새벽(00~06시) 마감 블록은 00시에 분석한다.
> 라인업·선발이 나온 뒤 분석하므로 정확도가 오르고, 같은 경기를 두 번 분석하지 않아 토큰을 아낀다.
> **분석이 끝나면 항상 커밋하고 원격(main, main:pacu)에 푸시한다.**

## A. 정기 작업 (00시·12시) — 회차 감시
1. `git pull --no-rebase origin pacu` (다른 PC 작업 반영, 충돌은 해결).
2. `python3 scripts/round_watch.py check` — 새 회차가 없으면 '새 회차 없음'. 새 회차면 등록(round_log init) + `분석일정.csv`에 블록 추가.
3. `python3 scripts/round_watch.py plan` — 대기 블록마다:
   - 분석 시각이 이미 지났거나 새벽 블록이면 → 지금 바로 B 절차.
   - 다음 12시간 안이고 아직 예약 안 됐으면(`분석일정.csv` 메모에 '예약됨' 없음) → `CronCreate` 일회성 작업을 분석 시각(분 단위를 :00/:30 피해서 1~2분 당김)에 건다.
     프롬프트: `[블록 분석] <회차>회 <블록> — 블록분석_절차.md B 절차대로` → 메모에 '예약됨' 기록.
4. `CronList`로 정기 작업(00·12시)의 남은 기간을 보고, 정기 작업은 7일이면 만료되니 하루 이하로 남았으면 같은 내용으로 다시 만든다.
5. 새 회차를 등록했을 때만 짧게 보고하고, 등록할 회차가 없으면 한 줄만 보고한다. 변경 파일은 커밋·푸시.

## B. 블록 분석 (블록 분석 시각)
1. `python3 scripts/round_watch.py games <회차> "<블록>"` → 이 블록 경기만 대상.
2. **배당을 보기 전에 순수 분석을 한다.** 경기 1~2개당 조사 에이전트(sonnet, 병렬)를 쓰고, 조사 프롬프트에 `종목별분석/<종목>.md`의 체크리스트와 리그 절, `종목별분석/변수태그.md`를 붙인다.
   - 기준선을 먼저 낸다: 축구 `soccer_baseline.py --league ... --home ... --away ...`, KBO `kbo_pitching.py --date`, MLB `mlb_pitching.py --date`.
   - **확정 라인업·선발·외국인 출전(KBL)을 반드시 확인한다**(마감 70분 전이라 대부분 발표됨).
   - 이미 순수 확률이 있는 경기(예: 120회)는 다시 내지 않고, 라인업·결장 변화만 확인해 '뉴스위험'·'제외'를 갱신한다.
   - 결과 CSV(홈,원정,순수_승,순수_무,순수_패,확신도,핵심근거,뉴스위험,제외,변수) → `round_log.py pure <회차> <파일>`, 제외 경기는 `data/exclude.json`.
3. **블록의 모든 경기를 분석한다** (사용자 지시 2026-10-10: 배당 1.3 미만·확률 60% 미만이어도 분석은 전부 — 회고·학습용). 추천 기준(1.3+·60%+)은 6단계에서만 적용한다.
   - 속도: 회차 전체 `round_log.py market`(10분 걸림) 대신 4번 스캔(블록만, --log) 후 `round_log.py market-from-scanlog <회차>`(스캔기록에서 시장 확률, 빠름) → `round_log.py adjust <회차>`(8%p 경고 확인).
   - 블록 경기 전체 분석표: 순수·뉴스 갱신 후 `python3 scripts/block_report.py <회차> "<블록>"` → `회차별분석/블록분석_<회차>_<MMDD-HHMM>.md` (기준선·순수·시장·최종·최고 선택지·근거·뉴스위험·추천/제외). 6단계 저장 뒤 한 번 더 돌려 추천/제외 칸을 채운다.
4. `odds_scan.py --round <회차> --best --log --close-from "<첫마감>" --close-to "<끝마감>"` → 이 블록 후보만.
5. 조합 고르기: 배당 1.3 이상, 확률 60% 이상, 순수·시장 일치 우선, 8%p 경고·제외·라인업 위험 경기 빼기, **비슷한 시각에 끝나는 경기끼리** 2~3경기, 1~3조합. 조합 안 경기 종료 예상 차이는 90분 이내(`pick_table.py` 경고).
6. `pick_table.py --round <회차> --save "제목=번호:선택,..." --skip "번호:선택=이유" ...`
   - 조합 마감이 분석 시각 + 60분보다 늦으면(같은 블록의 늦은 경기) 그 조합의 점검시각에 `CronCreate` 일회성 최종 점검(`final_check.py` + 라인업 확인 + PushNotification)을 건다.
7. 사용자에게는 **추천 조합 표만** 보여 준다(🕒 구매 시각 포함). 뺀 경기 설명은 하지 않는다. 추천이 없으면 '추천 없음 — 블록 N경기 분석 기록(파일명)' 한 줄.
8. `PushNotification` 한 줄: 예) "120회 10/10 오후 블록: 2조합 추천, 구매 13:30까지".
9. `round_watch.py done <회차> "<블록>"` → **커밋·푸시(main, main:pacu)**.

## C. 회고
회차가 끝나면 사용자가 "회고 진행해줘"라고 할 때 기존 회고 절차(CLAUDE.md 모드 2)를 따른다. 자동 루프는 회고를 하지 않는다.

## 제약
- `CronCreate` 작업은 이 Claude 세션 안에서만 산다(세션 종료·Mac 잠자기 시 멈춤). 정기 작업은 7일 뒤 만료되므로 A-4에서 갱신.
- 세션이 꺼졌다 다시 켜지면 사용자가 "루프 다시 켜줘"라고 하면 A 정기 작업을 다시 만든다.
