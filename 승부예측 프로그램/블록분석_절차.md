# 자동 루프 — 회차 감시와 마감 블록 분석 (사용자 지시 2026-10-10)

> 하루 한 번(**08시**, 베트맨 새 회차 오픈 시각 — 사용자 지시 2026-10-12. 이전엔 00·12시 두 번) 새 회차를 확인하고, 경기를 **판매 마감 시각별 블록**(첫 마감부터 60분 안에 마감되는 경기, 3경기 미만이면 90분 안 이웃 블록과 합침 — 최대한 같은 시간대끼리)으로 묶어 두었다가,
> **블록 마감 70분 전에 한 번만** 분석해서 조합을 추천한다. 새벽(00~06시) 마감 블록은 00시에 분석한다.
> 라인업·선발이 나온 뒤 분석하므로 정확도가 오르고, 같은 경기를 두 번 분석하지 않아 토큰을 아낀다.
> **분석이 끝나면 항상 커밋하고 원격(main, main:pacu)에 푸시한다.**

## A. 정기 작업 (08시, 하루 1회) — 회차 감시
1. `git pull --no-rebase origin pacu` (다른 PC 작업 반영, 충돌은 해결).
2. `python3 scripts/round_watch.py check` — 새 회차가 없으면 '새 회차 없음'. 새 회차면 등록(round_log init) + `분석일정.csv`에 블록 추가.
3. `python3 scripts/round_watch.py plan` — 대기 블록마다:
   - 분석 시각이 이미 지났거나 새벽 블록이면 → 지금 바로 B 절차.
   - 다음 24시간 안(다음 08시 정기 작업 전)이고 아직 예약 안 됐으면(`분석일정.csv` 메모에 '예약됨' 없음) → `CronCreate` 일회성 작업을 분석 시각(분 단위를 :00/:30 피해서 1~2분 당김)에 건다.
     프롬프트: `[블록 분석] <회차>회 <블록> — 블록분석_절차.md B 절차대로` → 메모에 '예약됨' 기록.
3-0. **승무패 감시 (사용자 요청 2026-10-12: "승무패 60회도 분석해줘")**: `python3 scripts/round_watch.py toto` — 미분석 승무패 회차가 있으면 그 자리에서 14경기 심층 분석을 한다(조사 에이전트 3~4개, `CLAUDE.md` 모드 1·3) 마킹 구성 — **4조합 기본 추천**(사용자 결정 2026-10-12) + 1조합·박빙 카운트 참고).
   - **마감 시각 자동 반영·한 번만 분석 (사용자 지시 2026-10-12)**: `toto`가 베트맨 `saleEndDate`를 읽어 `분석일정.csv`에 `승무패N / 마감 MM/DD HH:MM` 한 줄(분석시각 = **마감 2시간 전** — 14경기 심층이 30~40분 걸리고 구매 여유 필요, 2026-10-12 실측)을 넣는다. **발견 즉시 분석하지 않는다**(두 번 하면 토큰 낭비). 08시 정기 작업이 그 시각에 `CronCreate` 일회성 작업을 걸고, 그때 한 번에 14경기 2단계 심층(1차 7개 → [갈림]·[박빙]·[후보] 반론 → 후보·박빙 앙상블 2개) + Pinnacle 마감값·투표율(가치 1.2)로 `combo_optimizer` 1·4·`--gap 3 --max 8` → 마킹 표 + `PushNotification` → 커밋·푸시. 근거: 마감 배당이 오픈보다 정확(RPS z +3.2), 승무패 경기는 마감 뒤 2시간~1일 뒤 열려 라인업은 어차피 없다.
   - 59회 회고 규칙 적용: 무 마킹 = 시장 예상 총득점 최저권 + 무 근거(맞대결·홈 무·저득점) 겹치는 경기, 강팀 승 확률은 깎지 않고 시장 쪽.
   - `전체경기기록.csv`에 회차 `승무패<N>`으로 14경기 기록(순수·시장·마킹=구매 칸), `회차별분석/YYYY-MM-DD_승무패<N>_분석.md` 저장, 사용자에게 마킹 표 + 등위별 확률, 휴대폰 알림. 마감 전날 라인업 확인 예약(CronCreate)도 건다.
3-1. **학습 갱신 (매 정기 작업, 2026-10-10 학습 가속)**: `python3 scripts/round_log.py results <진행 회차>` → `python3 scripts/tracker.py results` → `python3 scripts/own_model.py report` → `python3 scripts/fast_learn.py`. 보고는 한 줄(예: "학습: 결과 채점 +12경기, 방향 적중 68%(60)"). 리그·변수에서 같은 방향 오류가 3회 이상 쌓이면 `종목별분석/<종목>.md` 편향 표에 [관찰]로 적는다(규칙 승격은 사용자 '회고' 때).
4. `CronList`로 정기 작업(08시)의 남은 기간을 보고, 정기 작업은 7일이면 만료되니 하루 이하로 남았으면 같은 내용으로 다시 만든다.
5. 새 회차를 등록했을 때만 짧게 보고하고, 등록할 회차가 없으면 한 줄만 보고한다. 변경 파일은 커밋·푸시.

## B. 블록 분석 (블록 분석 시각)
1. `python3 scripts/block_brief.py <회차> "<블록>"` → 이 블록 경기 한 줄 요약 + 2차·앙상블 대상 표시(토큰 절약 2026-10-12, `조사프롬프트.md` 절약 원칙). 스캔·adjust 뒤 한 번 더 돌려 표시를 확정한다(`adjust --quiet`).
2. **배당을 보기 전에 순수 분석을 한다.** 경기 1~2개당 조사 에이전트(sonnet, 병렬)를 쓰고, 조사 프롬프트에 `종목별분석/<종목>.md`의 체크리스트와 리그 절, `종목별분석/변수태그.md`를 붙인다.
   - 기준선을 먼저 낸다: 축구 `soccer_baseline.py --league ... --home ... --away ...`, KBO `kbo_pitching.py --date`, MLB `mlb_pitching.py --date`.
   - **확정 라인업·선발·외국인 출전(KBL)을 반드시 확인한다**(마감 70분 전이라 대부분 발표됨).
   - **모든 분석은 심층 분석 (사용자 지시 2026-10-12: "가능하면 모든 분석은 심층분석으로")** — 59회 2단계 심층이 시장 1순위보다 2경기 더 맞혔다.
     - 1차: 경기 1~2개당 조사 에이전트 — 결장·라인업, 최근 5경기 폼·xG, 홈/원정, 맞대결, 일정 피로, 동기, 감독·내부 이슈, **무승부 근거**(예상 총득점·맞대결 무·저득점), **이변 시나리오**.
     - 2차: 1차 뒤 ① 추천 후보 다리(60%+·1.2+), ② 순수·시장 8%p 이상 갈린 경기, ③ 1·2순위 차 3%p 미만 박빙 경기는 경기당 에이전트 1개로 반론(이 선택이 틀릴 이유) 조사 후 확정.
     - 이미 순수 확률이 있는 경기도 위 ①~③에 해당하면 2차를 한다(라인업 확인만으로 끝내지 않는다).
     - 결과로 **최종 판단 확률**(승/무/패)을 숫자로 남긴다(순수 칸 = 최종 판단, 핵심근거에 2차 결론).
     - **심층 강화 (사용자 승인 2026-10-12)** — 프롬프트는 `조사프롬프트.md`:
       결장 영향 숫자화(출전·득점 비중, 핵심 포지션 가중) · 현지 언어 매체 1곳 이상 · 박빙 경기 세부 변수(주심·날씨·이동·출전시간) ·
       추천 후보·3%p 박빙 경기는 독립 에이전트 2개 앙상블(1순위 10%p+ 차이·불일치면 '불확실' → 추천 제외/승무패 복수) ·
       `market_move.py <회차>`로 배당 흐름 확인('순수 반대 ⚠'면 2차 반론 대상).
   - 이미 순수 확률이 있는 경기(예: 120회)는 다시 내지 않고, 라인업·결장 변화만 확인해 '뉴스위험'·'제외'를 갱신한다.
   - 결과 CSV(홈,원정,순수_승,순수_무,순수_패,확신도,핵심근거,뉴스위험,제외,변수) → `round_log.py pure <회차> <파일>`, 제외 경기는 `data/exclude.json`.
3. **블록의 모든 경기를 분석한다** (사용자 지시 2026-10-10: 배당 1.2 미만·확률 60% 미만이어도 분석은 전부 — 회고·학습용). 추천 기준(1.2+·60%+)은 6단계에서만 적용한다.
   - 속도: 회차 전체 `round_log.py market`(10분 걸림) 대신 4번 스캔(블록만, --log) 후 `round_log.py market-from-scanlog <회차>`(스캔기록에서 시장 확률, 빠름) → `round_log.py adjust <회차>`(8%p 경고 확인).
   - **이변 가상 기록 (2026-10-12)**: adjust 뒤 `python3 scripts/upset_log.py scan <회차> "<블록>"` — 역배·무 후보(순수−시장 5%p+·기대값 1.05+)를 `data/이변기록.csv`에 남긴다. **추천표에 넣지 않고 사용자에게 보여 주지 않는다**(30건 판정 전). 정기 작업 3-1 학습 갱신 때 `upset_log.py report` 한 줄 보고.
   - 블록 경기 전체 분석표: 순수·뉴스 갱신 후 `python3 scripts/block_report.py <회차> "<블록>"` → `회차별분석/블록분석_<회차>_<MMDD-HHMM>.md` (기준선·순수·시장·최종·최고 선택지·근거·뉴스위험·추천/제외). 6단계 저장 뒤 한 번 더 돌려 추천/제외 칸을 채운다.
4. `odds_scan.py --round <회차> --best --log --close-from "<첫마감>" --close-to "<끝마감>"` → 이 블록 후보만.
5. 조합 고르기: 배당 1.2 이상, 확률 60% 이상, 순수·시장 일치 우선, 8%p 경고·제외·라인업 위험 경기 빼기, **비슷한 시각에 끝나는 경기끼리** 2~3경기, 1~3조합. 조합 안 경기 종료 예상 차이는 90분 이내(`pick_table.py` 경고).
   - **다리 수(사용자 지시 2026-10-12)**: 2다리 조합을 기본(적중 확률 최대)으로 하되, 3~4다리 다중 조합도 1개 함께 추천한다(적중 확률·배당 나란히, 다중은 확률이 2다리의 절반 이하임을 표시).
6. `pick_table.py --round <회차> --save "제목=번호:선택,..." --skip "번호:선택=이유" ...`
   - 조합 마감이 분석 시각 + 60분보다 늦으면(같은 블록의 늦은 경기) 그 조합의 점검시각에 `CronCreate` 일회성 최종 점검(`final_check.py` + 라인업 확인 + PushNotification)을 건다.
7. 사용자에게는 **추천 조합 표만** 보여 준다(🕒 구매 시각 포함). 뺀 경기 설명은 하지 않는다. 추천이 없으면 '추천 없음 — 블록 N경기 분석 기록(파일명)' 한 줄.
8. `PushNotification` 한 줄: 예) "120회 10/10 오후 블록: 2조합 추천, 구매 13:30까지".
9. `round_watch.py done <회차> "<블록>"` → **커밋·푸시(main, main:pacu)**.

## C. 회고
회차가 끝나면 사용자가 "회고 진행해줘"라고 할 때 기존 회고 절차(CLAUDE.md 모드 2)를 따른다. 자동 루프는 회고를 하지 않는다.

## 제약
- `CronCreate` 작업은 이 Claude 세션 안에서만 산다(세션 종료·Mac 잠자기 시 멈춤). 정기 작업은 7일 뒤 만료되므로 A-4에서 갱신.
- 세션이 꺼졌다 다시 켜지면 사용자가 "루프 다시 켜줘"라고 하면 A 정기 작업을 다시 만든다.
