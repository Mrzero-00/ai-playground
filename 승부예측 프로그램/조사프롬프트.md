# 조사 에이전트 프롬프트 (심층 분석 강화, 사용자 승인 2026-10-12)

> 블록 분석(B-2)·승무패 분석 때 조사 에이전트에 아래 블록을 붙인다. 종목 체크리스트(`종목별분석/<종목>.md`)와 `변수태그.md`도 함께 붙인다.
> 배당은 보지 말라고 지시한다(순수 분석). 결론은 승/무/패 % + 근거 + 출처.

## 1차 조사 (모든 경기)
```
[필수 항목]
1. 결장 영향 숫자화 — 결장/의문 선수마다: 포지션, 이번 시즌 출전시간 비중(%), 득점·도움(또는 xG+xA) 팀 내 비중(%), 대체 선수.
   포지션 가중치: 주전 GK·주전 CB·주포(팀 득점 25%+)는 '핵심', 나머지 주전은 '주요', 로테이션 자원은 '경미'.
   결론에 "결장 영향: 홈 핵심 n·주요 n / 원정 핵심 n·주요 n"을 한 줄로 쓴다. '확정'과 '의문'을 구분한다(의문은 0으로 계산).
2. 최근 5경기 폼(결과·득실·가능하면 xG), 홈/원정 성적, 맞대결 최근 5경기.
3. 일정 피로(직전·다음 경기 간격, 주중 대회, 이동), 동기(순위 경쟁·확정 여부), 감독·내부 이슈.
4. 무승부 근거: 두 팀 최근 득점 수준, 맞대결 무 비율, 예상 총득점 높낮이.
5. 이변 시나리오: 유력팀이 지지 않을/못 이길 구체적 이유 1~2개.
6. 홈 구장 인조잔디 여부(축구) — 인조잔디 홈 + 원정 강팀이면 강팀 승을 8~10%p 깎는다(분석규칙 2026-10-15 [중간], 3회 연속 이변).

[출처]
- 영어 매체에 더해 **현지 언어 매체를 반드시 1곳 이상** 검색한다(결장·라인업 소식이 몇 시간 빠르다):
  스페인 Marca·AS·Mundo Deportivo·구단 지역지(Noticias de Navarra 등) / 이탈리아 Gazzetta·Corriere dello Sport·구단 전문지 /
  독일 kicker·Sportschau·구단 지역지 / 프랑스 L'Équipe·Ouest-France·Maxifoot / 네덜란드 VI·NOS /
  일본 스포니치·닛칸스포츠·구단 공식 / 한국(KBO·KBL·K리그) 담당 기자 기사·구단 공식 SNS 보도.
- 같은 사실이 매체마다 다르면(예: '5연패 무득점') 두 곳 이상에서 확인될 때만 쓰고, 아니면 "미확인"이라고 쓴다.
```

## 2차 반론 조사 (추천 후보·8%p 갈림·3%p 박빙 경기)
```
이 경기에서 현재 판단은 <선택>(<확률>%)이다. 이 선택이 틀릴 이유를 찾는 데 집중하라.
- 1차에서 놓친 결장·복귀·라인업 변화, 상대의 강점이 통하는 전술 상성(압박 vs 빌드업, 포메이션 상성, 세트피스).
- 시장 과잉반응 점검(외부 연구 2026-10-12): 직전 1~2경기 대승·대패, 시즌 성적 대비 최근 부진, 인기 구단 홈경기로 배당이 한쪽에 쏠렸는가 — 쏠렸다면 반대쪽(역배·무) 확률을 1~3%p 안에서 검토.
- [박빙 경기만] 세부 변수: 주심 성향(경기당 카드·페널티), 날씨·잔디, 이동거리, 주중 경기 출전시간.
결론: 판단 유지/수정 + 수정 시 승/무/패 %.
```

## 앙상블 (추천 후보·3%p 박빙 경기만 — 토큰 2~3배라 전체에는 쓰지 않음)
- 같은 경기를 **서로 결과를 모르는 에이전트 2개**에 1차 프롬프트로 따로 맡긴다(병렬).
- 최종 판단 = 두 결과 평균(+ 기존 1차). **두 에이전트의 1순위 확률 차가 10%p 이상이거나 1순위가 다르면 '불확실'**:
  프로토는 추천에서 빼고, 승무패는 그 경기를 복수 마킹 후보로 올린다.
- 사실 관계가 서로 다르면(한쪽만 결장 보도) 그 사실만 한 번 더 확인한다.

## 배당 흐름 신호 (스크립트, 비용 없음)
- `python3 scripts/market_move.py <회차> [번호 ...]` — 첫 수집 대비 최신 Pinnacle 공정확률 이동.
  '순수 쪽 ✓' = 시장도 같은 정보를 반영(확신 유지), '순수 반대 ⚠ 재조사' = 내가 모르는 정보 가능성 → 2차 반론 대상에 넣는다.
- 120회 소급: 팰리스-노팅엄은 시장이 노팅엄 쪽으로 움직였지만 순수(무 39%)와 반대 신호였고 결과는 팰리스 승 — 신호는 근거 중 하나일 뿐 결과 판정은 회고에서 누적한다.

## 토큰 절약 원칙 (2026-10-12 — 0순위 정확도는 유지, 같은 정보를 두 번 사지 않는다)
1. **대상 자동 선별**: 블록 분석 첫 단계는 `python3 scripts/block_brief.py <회차> "<블록>"` 한 번. 경기당 한 줄 + [후보]·[갈림]·[박빙]·[흐름⚠] 표시.
   표시 없는 경기는 1차만, 표시 경기만 2차, [후보]·[박빙]만 앙상블. (여러 grep·스캔 출력·adjust 전체 표를 읽지 않는다 — `adjust --quiet`, `block_report.py`는 저장만, 표가 필요하면 `--print`.)
2. **팀노트 캐시**: 에이전트는 먼저 `팀노트/<팀명>.md`를 읽는다. 7일 안에 갱신된 노트가 있으면 순위·장기 결장·전술 같은 느린 정보는 다시 찾지 않고,
   **노트 날짜 이후 뉴스(결장·라인업·감독)만** 검색한다. 끝나면 새로 확인한 사실을 날짜와 함께 노트에 덧붙인다(출처 1줄).
   → 같은 팀이 프로토 여러 블록·승무패·다음 회차에 다시 나와도 느린 정보는 한 번만 조사.
3. **프로토·승무패 공유**: 승무패 14경기는 대부분 같은 주 프로토 회차에도 있다. 한쪽에서 낸 최종 판단 확률을 다른 쪽에 그대로 쓰고, 마감이 더 늦은 쪽에서는 라인업·결장 변화만 확인한다.
4. **묶음 조사**: 같은 리그 경기는 에이전트 하나에 2~3경기(리그 순위표·일정 조회를 한 번에). 2차 반론도 대상 경기 2개씩 묶는다. 앙상블만 경기별 독립.
5. **모델 배정**: 1차·2차·앙상블 = sonnet(정확도). 결과 수집·경기 후 기사 요약·라인업 발표 여부 확인 같은 사실 조회 = haiku.
   결과 채점은 베트맨 공식 결과(`round_log.py results`, `tracker.py results`)가 먼저 — 웹 검색은 틀린 경기의 원인 조사에만.
6. **보고 형식 고정(짧게)**: 에이전트 답은 경기마다
   `경기 | 승/무/패 % | 확신도 | 결장 영향(홈 핵심n·주요n / 원정 핵심n·주요n) | 핵심근거 1줄 | 뉴스위험 1줄 | 무 근거 1줄 | 이변 1줄 | 출처 2~3개`
   + 2차는 `유지/수정 | 수정 확률 | 이유 1줄`. 이 줄이 그대로 `round_log.py pure` CSV가 된다. 서론·요약 문단 금지.
7. **검색 상한**: 1차 경기당 검색 6회, 2차 4회 안에서 끝낸다(현지 매체 1회 포함). 상한에서 모자란 정보는 '미확인'으로 쓰고 뉴스위험에 올린다.
8. **시장 없는·정보 빈약 리그**(중국 슈퍼리그 하위·하부리그 등 Pinnacle 매칭 없음): 1차 검색 3회로 줄이고 자료 부족이면 바로 '제외'. 추천이 나올 수 없는 경기에 2차를 쓰지 않는다(학습 기록은 남김).

## 검색 한도 소진 시 (2026-10-13)
- Claude Code WebSearch는 세션당 약 500회에서 막히고 서브에이전트도 같은 예산을 쓴다(설정으로 증설 불가). 소진되면 에이전트 프롬프트에 아래를 붙인다:
  "WebSearch 대신 WebFetch로 ① https://search.brave.com/search?q=<검색어+> ② https://news.google.com/rss/search?q=<검색어+>&hl=<언어>&gl=<국가>&ceid=<국가>:<언어> 를 쓴다(현지어 매체는 hl/gl/ceid 변경). DuckDuckGo·Bing은 막힘."
- 근본 해결 후보: MCP 검색 서버(Brave Search·Tavily, API 키 필요).
