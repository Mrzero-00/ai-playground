# 한강에서 온 편지 — PRD

문서 버전: v0.1
작성 기준일: 2026-09-02
제품 유형: 앱인토스 비게임 미니앱
대상 릴리스: MVP

## 1. 문서 목적

본 문서는 “한강에서 온 편지” MVP의 제품 목표, 범위, 기능·정책·화면·수용 기준을 정의한다. 서비스 기획, 디자인, 개발, QA, 운영이 동일한 규칙으로 의사결정하는 기준 문서로 사용한다.

## 2. 제품 요약

사용자는 텍스트 편지를 익명으로 한강에 띄운다. 편지는 일정 시간 흐른 뒤 운영 중인 한강공원과 공원 내 안전 탐색 영역의 좌표에 무작위로 도착한다. 지도에는 공원별 미획득 편지 개수만 공개된다. 사용자는 정확한 위치, 거리, 방향 안내 없이 공원 안을 직접 탐색하고, 숨은 좌표 가까이에서 카메라 기반 AR풍 병을 발견한다. 서버가 위치와 선점 여부를 검증한 뒤 최초 한 사람에게만 편지를 공개한다.

## 3. 목표와 비목표

### 3.1 MVP 목표

- 편지 작성→표류→무작위 공원 도착→현장 탐색→1인 획득의 전체 루프를 검증한다.
- 공원명과 편지 개수만으로도 사용자가 현장 탐색을 시작하는지 확인한다.
- 위치와 카메라 권한을 최소한으로 사용하면서 획득 성공률을 확보한다.
- 무작위 익명 콘텐츠를 안전하게 운영할 수 있는 사전·사후 통제 체계를 만든다.
- 앱인토스 비게임 미니앱의 정책·기능·디자인·보안 검수를 통과한다.

### 3.2 비목표

- MVP에서 답장, 댓글, 채팅을 제공하지 않는다.
- 공개 피드, 팔로우, 인기 순위, 프로필을 만들지 않는다.
- 사진·음성·동영상·링크 첨부를 지원하지 않는다.
- 편지를 특정 사용자에게 보내거나 발신자와 수신자의 신원을 공개하지 않는다.
- 현금성 보상, 토스 포인트, 광고, 결제를 제공하지 않는다.
- 실제 수면·지면 인식이나 3D 공간 고정 수준의 완전한 AR을 보장하지 않는다.

| 편지 내용 | 텍스트 1~500자, URL·연락처·첨부 금지 |

## 5. 사용자와 권한

### 5.1 사용자 역할

- 발신자: 편지를 작성해 띄우고 상태를 확인하는 사용자
- 탐색자: 공원별 편지 개수를 확인하고 현장에서 찾는 사용자
- 획득자: 최초로 편지를 획득해 내용을 읽을 수 있는 사용자
- 운영자: 편지, 신고, 사용자 제재, 공원·안전 영역을 관리하는 사용자

동일 사용자가 모든 일반 역할을 가질 수 있다.

### 5.2 식별

- 앱인토스 비게임용 익명 사용자 식별키를 사용한다.
- 서비스 서버에는 원본 식별키 대신 비가역 가명 식별값을 저장한다.
- 실명, 전화번호, 이메일, 토스 프로필 정보는 MVP에서 수집하지 않는다.
- 식별키를 받지 못한 경우 읽기 전용 인트로까지만 허용하고 재시도 안내를 제공한다.

### 5.3 권한 요청 원칙

- 앱 진입 시 위치·카메라 권한을 요청하지 않는다.
- 위치 권한은 사용자가 “편지 찾기”를 선택하고 목적 안내를 확인한 뒤 요청한다.
- 카메라 권한은 현장 찾기 화면에서 “카메라로 찾기”를 선택한 뒤 요청한다.
- 권한을 거부해도 편지 작성, 표류 상태, 주운 편지 열람은 이용 가능하다.
- OS에서 영구 거부한 경우 설정 변경 경로와 카메라 폴백을 안내한다.

## 6. 핵심 사용자 여정

### 6.1 편지 보내기

1. 홈에서 “편지 띄우기”를 선택한다.
2. 감정 태그를 최대 1개 선택하거나 건너뛴다.
3. 1~500자의 본문을 입력한다.
4. 무작위 성인에게 전달된다는 점과 금지 콘텐츠를 확인한다.
5. 제출하면 연락처·URL 형식 검사와 자동 콘텐츠 검수를 진행한다.
6. 통과 시 병을 띄우는 연출과 표류 예정 시간을 보여준다.
7. “내 편지”에서 검수·표류·도착·획득·재표류·만료 상태를 확인한다.

### 6.2 편지 찾기

1. 홈 지도에서 “○○한강공원에 편지 N개가 떠내려왔어요”를 확인한다.
2. 공원 카드를 선택하면 개수, 운영 상태, 안전 안내만 표시한다.
3. 공원에 도착한 뒤 “찾기 시작”을 누른다.
4. 위치 권한을 허용하면 앱은 사용자가 해당 공원 탐색 영역 안인지 확인한다.
5. 찾기 화면은 정확한 좌표·거리·방향을 표시하지 않는다.
6. 사용자는 공원 안을 이동한 뒤 멈춰서 카메라로 주변을 확인한다.
7. 숨은 좌표의 획득 반경 안이면 병이 나타난다.
8. 병을 터치하면 서버가 짧은 유효시간의 획득 증표와 선점 여부를 검증한다.
9. 최초 성공자에게만 편지 봉인이 열리고 본문이 보인다.

### 6.3 선점과 실패

- 같은 편지를 여러 명이 동시에 찾을 수 있으나 최초 원자적 획득 요청만 성공한다.
- 실패한 사용자는 “다른 사람이 먼저 편지를 발견했어요”를 확인하고 공원 잔여 개수로 돌아간다.
- GPS 정확도가 기준보다 낮으면 사용자가 멈춘 상태에서 재시도하도록 안내한다.
- 공원 운영이 중지되면 찾기를 시작할 수 없고 이미 도착한 편지는 재표류 처리한다.

## 9. 상태 모델

### 9.1 편지 상태

`MODERATION_PENDING → DRIFTING → LANDED → CLAIMED`

예외 상태는 다음과 같다.

- `REJECTED`: 자동 또는 사람 검수에서 발송 거절
- `RELOCATING`: 24시간 미획득 또는 운영 중지로 다른 공원 재선정 중
- `EXPIRED`: 최대 공원·시간 상한 도달
- `HIDDEN`: 신고 검토 중 임시 숨김
- `REMOVED`: 운영 정책 위반 확정 삭제

### 9.2 허용 전이

| 현재 | 다음 | 트리거 |
|---|---|---|
| MODERATION_PENDING | DRIFTING | 검수 통과 |
| MODERATION_PENDING | REJECTED | 검수 거절 |
| DRIFTING | LANDED | 표류 종료 시각 도달 및 좌표 생성 성공 |
| LANDED | CLAIMED | 최초 유효 획득 트랜잭션 성공 |
| LANDED | RELOCATING | 24시간 미획득 또는 공원 운영 중지 |
| RELOCATING | LANDED | 새 공원·좌표 생성 성공 |
| LANDED/RELOCATING | EXPIRED | 3개 공원 또는 72시간 상한 도달 |
| LANDED/CLAIMED | HIDDEN | 고위험 신고 또는 운영자 조치 |
| HIDDEN | LANDED/CLAIMED | 검토 결과 문제 없음 |
| HIDDEN | REMOVED | 위반 확정 |

## 10. 비즈니스 규칙

- 동일 사용자는 자신의 편지 본문을 “내 편지”에서 볼 수 있으나 획득자로 기록될 수 없다.
- 공원별 공개 개수는 `LANDED`이면서 숨김·만료·획득되지 않은 편지만 센다.
- 재표류 시 같은 공원은 후보에서 제외한다. 남은 공원이 없으면 이전 공원을 허용하되 다른 안전 영역을 선택한다.
- 무작위 공원 선택은 운영 가능한 후보 집합 안에서 균등하게 한다. 인기·유료·사용자별 가중치를 적용하지 않는다.
- 무작위 좌표는 안전 영역의 면적을 기준으로 균등하게 생성한다.
- 편지 실제 좌표는 운영자 최소 권한과 서버 판정 로직만 접근한다.
- 획득 반경, 정확도 한계, 공원 체류 시간, 발송·획득 제한은 운영 설정값으로 관리한다.
- 사용자의 원본 위치는 분석 이벤트, 접근 로그, 오류 로그에 포함하지 않는다.

## 11. 수용 기준

### AC-01 편지 발송

- 사용자가 유효한 1~500자 본문을 제출하면 검수 결과에 따라 `DRIFTING` 또는 `REJECTED`가 된다.
- URL·연락처 패턴이 있으면 제출되지 않고 수정 위치를 안내한다.
- 일일·동시 발송 제한을 넘으면 제한 해제 시점을 안내한다.

### AC-02 무작위 도착

- 동일 조건에서 충분한 표본을 생성했을 때 특정 활성 공원이 의도치 않게 제외되지 않는다.
- 생성된 모든 좌표는 안전 탐색 영역 안이고 제외 영역 및 이격 기준 밖이다.
- 클라이언트와 공개 API에서는 생성 좌표를 확인할 수 없다.

### AC-03 공원별 재고

- 홈에서 각 활성 공원의 미획득 편지 개수가 보인다.
- 편지 획득·재표류 후 해당 공원 개수가 10초 안에 감소한다.
- 개수가 0이면 “지금은 도착한 편지가 없어요”를 표시한다.

### AC-04 현장 탐색

- 사용자가 공원 밖이면 찾기 시작이 제한된다.
- 공원 안이지만 목표 반경 밖이면 좌표·거리·방향 없이 탐색 상태를 유지한다.
- 목표 반경 안이고 위치 정확도가 기준을 충족하면 발견 증표가 발급된다.
- 카메라 권한 거부 시 사진 촬영 재요청 또는 위치 기반 대체 연출 경로가 제공된다.

### AC-05 독점 획득

- 같은 편지에 동시 획득 요청 100건을 보내도 정확히 1건만 성공한다.
- 성공 응답에만 편지 본문이 포함된다.
- 실패 사용자는 선점 안내 후 갱신된 공원 개수를 본다.
- 발신자의 획득 요청은 항상 실패한다.

### AC-06 재표류

- 24시간 미획득 편지는 `RELOCATING`을 거쳐 다른 무작위 공원에 도착한다.
- 최대 3개 공원 또는 72시간 뒤에는 `EXPIRED`가 되고 공개 개수에서 제외된다.
- 운영자가 공원을 중지하면 그 공원의 모든 미획득 편지는 재표류 큐로 이동한다.

### AC-07 신고

- 신고 접수 직후 신고자에게 편지가 다시 노출되지 않는다.
- 고위험 사유는 전체 노출을 즉시 중단한다.
- 운영 조치와 복구가 감사 로그에 남는다.
