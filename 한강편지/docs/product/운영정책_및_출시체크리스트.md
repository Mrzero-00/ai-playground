# 한강에서 온 편지 — 운영정책 및 출시 체크리스트

문서 버전: v0.1
작성 기준일: 2026-09-02
상태: 운영·법률·앱인토스 검수 준비용 초안

## 1. 운영 목표

운영의 최우선 목표는 사용자가 위험한 장소로 이동하지 않고, 불쾌하거나 위법한 콘텐츠에 노출되지 않으며, 위치정보와 익명성이 과도하게 사용되지 않도록 하는 것이다. 편지 수와 탐색자 수의 균형을 유지해 헛걸음과 장기 미획득을 줄이는 것도 핵심 운영 책임에 포함한다.

## 2. 역할과 책임

| 역할 | 주요 책임 |
|---|---|
| 제품 책임자 | 정책 결정, KPI, 공원 확대·중지, 앱인토스 협의 |
| 콘텐츠 운영자 | 보류 편지 검수, 신고 처리, 사용자 제재, 이의 확인 |
| 공원 안전 담당 | 현장 답사, 안전·제외 영역 등록, 날씨·행사 중지 |
| 고객지원 | 권한·획득·신고·삭제 문의, 장애 공지 |
| 개발·보안 | 장애·취약점·데이터 삭제, 감사 로그, 백업·복구 |
| 개인정보·법률 담당 | 위치정보·개인정보·약관·위탁·신고 검토 |

한 사람이 여러 역할을 맡더라도 고위험 콘텐츠 복구, 영구 제재, 대량 데이터 조회는 가능하면 2인 확인을 적용한다.

## 3. 콘텐츠 운영정책

### 3.1 허용 콘텐츠

- 일상, 감정, 위로, 응원, 감사, 가벼운 고민과 질문
- 불특정 성인에게 전달되어도 안전한 비상업적 내용
- 특정 개인을 식별하거나 공격하지 않는 개인적 경험

### 3.2 금지 콘텐츠

| 범주 | 예시 | 기본 조치 |
|---|---|---|
| 개인정보·연락 유도 | 전화번호, 이메일, SNS ID, 주소, 실명+소속 | 발송 차단 |
| 만남·거래 유도 | 특정 장소·시간 만남, 송금·판매·구매 요청 | 발송 차단 |
| 괴롭힘·혐오 | 개인·집단 모욕, 차별, 위협 | 차단·반복 시 제재 |
| 성적·착취 | 노골적 성적 표현, 착취·그루밍, 불법 촬영 | 즉시 차단·중대 제재 |
| 폭력·불법 | 범죄 조장, 구체적 위해·제조·침입 방법 | 즉시 차단·중대 제재 |
| 자해·타해 | 구체적 방법, 조장, 협박 | 공개 보류·사람 검수·필요 시 도움 안내 |
| 광고·스팸 | URL, 반복 홍보, 이벤트·쿠폰·리워드 유도 | 차단·반복 시 발송 제한 |
| 사칭·기만 | 운영자·기관 사칭, 허위 긴급 상황 | 차단·중대 제재 |

### 3.3 검수 의사결정

- PASS: 즉시 표류 시작
- HOLD: 사용자에게 “확인 중”을 표시하고 사람 검수
- REJECT: 발송하지 않고 일반적 수정 안내 제공
- REMOVE: 발송 후 신고나 재검수로 전체 노출 중지

검수 결과에 위험 문장을 그대로 재노출하지 않는다. 모델 점수만으로 영구 제재하지 않고 반복 위반·명백한 고위험 콘텐츠를 제외하면 사람이 확인한다.

### 3.4 신고 처리

1. 신고자 화면에서 즉시 편지를 숨긴다.
2. 위협·성적 착취·자해·불법 등 고위험 사유는 전체 노출을 즉시 중지한다.
3. 운영자가 본문, 자동 검수 결과, 이전 위반 이력을 최소 범위로 확인한다.
4. 문제 없음, 편지 삭제, 경고, 발송 제한, 영구 차단 중 하나를 결정한다.
5. 조치와 사유를 감사 로그에 남긴다.

### 3.5 처리 목표

| 우선순위 | 범주 | 최초 조치 목표 | 최종 처리 목표 |
|---|---|---|---|
| 긴급 | 구체적 위해·착취·불법·개인정보 대량 노출 | 자동 즉시 숨김 | 2시간 이내 |
| 높음 | 괴롭힘·혐오·성적 내용·자해 위험 | 즉시 또는 10분 이내 숨김 | 24시간 이내 |
| 일반 | 광고·불쾌감·기타 정책 위반 | 신고자 즉시 숨김 | 48시간 이내 |

24시간 상시 사람 운영이 불가능하면 야간에는 고위험을 자동 숨김 상태로 유지하고 운영 시간 시작 후 우선 검수한다.

## 4. 사용자 제재

| 단계 | 조건 예시 | 조치 |
|---|---|---|
| 안내 | 경미한 1회 위반 | 편지 거절과 정책 안내 |
| 경고 | 반복 경미 위반 | 경고 기록, 당일 발송 제한 |
| 기간 제한 | 중간 위험 또는 다회 반복 | 7~30일 발송 제한 |
| 영구 차단 | 구체적 위협·착취·중대한 불법·회피 반복 | 신규 발송 영구 금지 |

- 제재 사용자는 주운 편지 열람, 데이터 삭제, 고객문의에 접근할 수 있어야 한다.
- 사용자 식별키 변경 등 우회 패턴은 최소한의 데이터로 탐지한다.
- 악성 신고자에게는 신고 속도 제한을 적용하되 정상 신고 경로를 완전히 막지 않는다.

## 5. 공원과 무작위 좌표 운영

### 5.1 공원 등록 체크리스트

- [ ] 공원 관리 경계와 사용자에게 표시할 중심점 등록
- [ ] 평일·주말·야간 현장 답사
- [ ] 보행 가능한 안전 탐색 영역 다각형 등록
- [ ] 수변, 차도, 자전거도로, 계단, 급경사, 공사·행사 구역 제외
- [ ] 제외 영역별 추가 이격거리 설정
- [ ] GPS 정확도·통신 품질 표본 측정
- [ ] 운영 시간, 야간 제한, 최대 재고, 획득 반경 설정
- [ ] 장애인·유아차 접근과 대체 지점 확인
- [ ] 긴급 중지 담당자와 연락 체계 확인
- [ ] 무작위 좌표 20개 이상 블라인드 도보 테스트

### 5.2 무작위성 원칙

- 활성·재고 여유·안전 영역 보유 공원 안에서 균등하게 선택한다.
- 선택한 공원 안에서는 안전 탐색 영역의 면적 기준으로 좌표를 무작위 생성한다.
- 위험 구역을 후보에서 제외하는 것은 무작위성 훼손이 아니라 서비스 안전 조건이다.
- 운영자는 특정 개인에게 유리하도록 좌표를 임의 제공·변경하지 않는다.
- 사용자 화면에는 공원명과 미획득 편지 개수만 보여준다.

### 5.3 재표류 운영

- 한 공원에서 24시간 발견되지 않으면 편지를 `RELOCATING` 상태로 바꾼다.
- 이전 공원을 제외한 활성 공원을 다시 무작위 선택한다.
- 최대 3개 공원 또는 72시간 뒤 만료한다.
- 공원 긴급 중지 시 해당 공원의 모든 편지를 즉시 재표류시킨다.
- 재표류 작업 실패가 5분 이상 지속되면 운영자에게 알린다.

### 5.4 공원 중지 조건

- 호우·홍수·강풍·폭염·한파 등 현장 활동이 위험한 경우
- 침수, 공사, 통제, 대형 행사, 시위, 야간 출입 제한
- GPS·통신 장애로 획득 실패율이 급증한 경우
- 현장 민원 또는 안전사고가 접수된 경우

중지 시 홈의 편지 개수를 즉시 0으로 보이게 하고 “지금은 찾을 수 없어요”를 표시한다.

## 6. 현장 안전 UX

- 사용자가 걷는 동안 카메라만 보도록 유도하지 않는다.
- 탐색 시작과 일정 시간마다 “안전한 곳에 멈춰서 확인해 주세요”를 표시한다.
- 자전거·킥보드·차량 이동 중 사용 금지 안내를 제공한다.
- 강변, 차도, 자전거도로, 통제구역으로 들어갈 필요가 없음을 명확히 알린다.
- 카메라를 좌우로 크게 휘두르거나 타인을 촬영하도록 지시하지 않는다.
- 현장 사진은 기본적으로 서버에 저장하거나 공유하지 않는다.
- 편지가 선점되면 추가 이동을 유도하기 전에 공원 잔여 개수를 갱신한다.

## 7. 개인정보·위치정보 준비

본 절은 출시 전 법률 검토 체크리스트이며 법률 자문을 대체하지 않는다.

### 7.1 위치정보

서비스는 사용자의 현재 위치를 이용해 현장 탐색과 획득 가능 여부를 판단한다. 개인위치정보를 대상으로 위치기반서비스사업을 하는 경우 위치정보법 제9조의 신고 대상이 될 수 있으므로 사업 구조, 운영 주체, 위탁 관계를 기준으로 출시 전에 전문 검토한다.

- [ ] 위치기반서비스사업 신고 대상과 시점 확인
- [ ] 위치기반서비스 이용약관 필요 항목과 공개 경로 확인
- [ ] 위치정보관리책임자, 보호조치, 이용·제공 사실 기록 범위 확인
- [ ] 위치 사용 목적·항목·보유 기간·동의 철회 경로 확정
- [ ] 원본 위치 미저장 설계와 로그 마스킹 검증
- [ ] 외부 지도·분석·오류 도구로 위치가 전달되지 않는지 확인
- [ ] 사용자 탈퇴·삭제 시 위치 관련 기록 처리 기준 확정

### 7.2 개인정보 처리방침

- 처리 목적, 항목, 법적 근거·동의, 보유 기간
- 제3자 제공, 처리 위탁, 국외 이전 여부
- 파기 절차, 사용자 권리와 행사 방법
- 개인정보 보호책임자·문의·침해 구제 경로
- 자동 콘텐츠 검수, 분석, 오류 추적 도구의 수탁자와 처리 항목
- 앱인토스 익명 식별키의 수집·가명처리 방식

### 7.3 권장 최소 보유안

| 데이터 | 권장 초안 | 비고 |
|---|---|---|
| 원본 사용자 현재 좌표 | 저장하지 않음 | 요청 처리 메모리에서만 사용 |
| 정확한 편지 목표 좌표 | 활성 기간 + 분쟁 대응 7일 | 이후 삭제 또는 공원 단위 축약 |
| 미획득 만료 편지 본문 | 만료 후 30일 | 이의·운영 확인 후 삭제 |
| 획득 편지 본문 | 사용자 보관 기능 정책에 따름 | 삭제·탈퇴 경로 제공 |
| 신고·제재 기록 | 90일 또는 법률 검토 결과 | 중대 사건은 별도 기준 |
| 일반 접속·보안 로그 | 30일 | 본문·원본 위치 제외 |

보유 기간은 서비스 운영 목적, 법정 의무, 사용자 고지와 일치하도록 최종 확정한다.

## 8. 앱인토스 출시 준비

### 8.1 서비스·디자인

- [ ] 비게임 카테고리와 위치 기반 UGC 구조를 앱인토스에 사전 문의
- [ ] 앱 이름, appName, 아이콘, 설명, 검색 키워드, 고객문의 이메일 확정
- [ ] 콘솔에 등록한 앱 내 기능과 실제 스킴이 모두 정상 동작
- [ ] 비게임 공통 내비게이션, 뒤로가기, 종료, 더보기·신고 흐름 확인
- [ ] 라이트 모드와 TDS 모달·컴포넌트 적용
- [ ] 앱 진입 직후 권한·바텀시트로 행동을 강제하지 않음
- [ ] CTA 문구가 다음 행동을 예측할 수 있게 작성
- [ ] 권한 거부 후에도 편지 쓰기·보관함이 정상 동작
- [ ] 불법·선정·괴롭힘 콘텐츠의 사전 차단과 신고 기능 시연 가능

### 8.2 개발·보안

- [ ] 최신 SDK 2.x와 지원 토스 앱 버전 확인
- [ ] SSR, iframe, eval 미사용
- [ ] 번들 압축 해제 크기 100MB 미만
- [ ] 위치·카메라 권한 선언과 목적 안내
- [ ] 실시간 카메라 실패 시 공식 촬영 API 폴백
- [ ] mTLS 인증서·개인키가 클라이언트와 저장소에 없음
- [ ] 외부 연결은 HTTPS/WSS만 사용
- [ ] 원본 위치·편지 본문·익명 식별키가 로그에 없음
- [ ] 탈퇴·동의 철회·사용자 식별 연결 해제 시 데이터 처리 확인

### 8.3 테스트·검수

- [ ] 샌드박스와 출시 QR 실제 토스 앱에서 모두 테스트
- [ ] iOS·Android 권한 허용·거부·영구 거부 테스트
- [ ] 모든 화면 뒤로가기와 앱 종료 동작 확인
- [ ] 공원 0개·1개·다수 편지 상태 확인
- [ ] 두 기기 동시 획득에서 한 명만 성공
- [ ] 24시간 재표류와 72시간 만료 시간 가속 테스트
- [ ] 공원 중지 후 편지 재표류와 사용자 안내 확인
- [ ] 신고 즉시 숨김·운영 조치·감사 로그 확인
- [ ] 네트워크 끊김·저속·재시도에서 중복 편지·중복 획득 없음

현재 공식 FAQ는 앱인토스 비게임 출시가 서비스 범위와 검수에 따라 약 1~3개월 걸릴 수 있다고 안내한다. 내부 개발 일정과 별도로 사전 상담, 서류, 검수·재검수 여유를 둔다.

## 9. 고객지원 기준

### 9.1 문의 유형

- 위치·카메라 권한을 허용했지만 찾기가 시작되지 않음
- 공원에 편지가 표시되지만 발견되지 않음
- 병을 터치했는데 다른 사용자가 먼저 획득함
- 내가 띄운 편지가 거절·재표류·만료됨
- 불쾌한 편지 신고와 처리 상태
- 내 데이터 열람·삭제·탈퇴

### 9.2 답변 원칙

- 실제 편지 좌표를 고객지원이 사용자에게 제공하지 않는다.
- 다른 사용자의 신원·접속·획득 기록을 제공하지 않는다.
- 안전 우려가 있으면 해당 공원을 우선 중지하고 확인한다.
- 권한 문제는 OS 설정 안내 후에도 해결되지 않으면 앱 버전·OS·오류 시각만 수집한다.
- 편지 본문이나 사용자 위치 스크린샷 제출을 기본 요구하지 않는다.

## 10. 사고 대응

### 10.1 등급

| 등급 | 예시 | 초기 대응 목표 |
|---|---|---|
| SEV-1 | 위치·본문 대량 노출, 현장 중대 사고, 획득 소유권 광범위 오류 | 15분 내 기능 중지·책임자 호출 |
| SEV-2 | 특정 공원 오좌표, 검수 전면 장애, 신고 숨김 실패 | 30분 내 공원/기능 중지 |
| SEV-3 | 일부 권한·카메라 오류, 재고 갱신 지연 | 영업시간 4시간 내 완화 |

### 10.2 기본 절차

1. 영향을 받는 공원 또는 기능을 기능 플래그로 중지한다.
2. 신규 편지 도착·scan·claim을 필요 범위만큼 차단한다.
3. 원본 데이터 변형 전 감사 로그와 증거를 보존한다.
4. 개인정보 사고 여부와 신고·통지 의무를 담당자가 판단한다.
5. 사용자에게 영향과 안전한 다음 행동을 공지한다.
6. 복구 후 원인·재발 방지·지표를 기록한다.

## 11. 일일·주간 운영 루틴

### 매일

- 검수 보류·신고 큐와 SLA 확인
- 공원별 재고 0·상한·장기 미획득 상태 확인
- 위치·카메라 오류율과 claim 선점 실패율 확인
- 날씨·행사·공사로 중지할 공원 확인
- 스케줄러, 검수사, 데이터베이스, 인증서 경고 확인

### 매주

- 공원별 탐색 시간·획득률·재표류율 비교
- 자동 검수 오탐·미탐 표본 평가
- 무작위 좌표 분포와 위험 구역 근접 좌표 감사
- 반복 신고·제재 패턴과 정책 변경 필요성 검토
- 운영자가 본문·좌표를 과도하게 조회하지 않았는지 감사 로그 확인

| 보안 | 비밀·인증·암호화·취약점·감사 로그 확인 | 보안 담당 | 미정 |

## 13. 익명 채팅 고도화 전 추가 게이트

편지 획득자 한정 익명 채팅은 MVP 이후 별도 PRD로 진행한다. 다음 항목 없이는 출시하지 않는다.

- 획득자만 요청 가능하고 발신자가 명시적으로 수락하는 이중 동의
- 메시지 실시간 안전 필터와 사후 검수
- 대화방 차단·나가기·영구 종료·신고
- 연락처·외부 메신저·만남 유도 차단
- 반복 메시지·야간 괴롭힘·성적 접근 방지 제한
- 채팅 보유·삭제·운영자 열람 정책과 개인정보 고지
- 중대한 위해 상황 대응 절차와 운영 인력
